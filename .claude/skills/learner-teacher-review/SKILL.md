# 학습자–교사 토론 검증 (Learner–Teacher Review)

작업 디렉터리 **/Users/quantcommander/EduViz**. 먼저 `CLAUDE.md` §5.6(서술 규칙)·§5.7(이 절차의 원칙)을 읽는다.
기준은 하나: **"이 내용을 처음부터 순서대로 따라가면 체계적으로 이해되는가."**

## 0. 범위 정하기 (Advisor)
1. 대상 목록을 **학습 순서대로** 뽑는다(허브·목차의 실제 순서. 번호 순서가 아님 — 허브 순서 역전이 실제로 가장 큰 결함이었다).
2. 구간을 나눈다: 학습자·교사 한 쌍이 맡을 분량은 **페이지(실험실) 4~7편 또는 장면 25~40개**. 구간끼리 파일이 겹치지 않게.
3. 토론 기록 위치(비공개, 커밋 안 됨): Agent Lab = `_content/FDC/_teach/debate/segN.md`, ADP = `_content/BDA/_teach/debate/`, 그 밖의 트랙 = `_content/<트랙>/_review/segN.md`.
4. 비용 안내: 학습자·교사 한 쌍 × 2라운드 ≈ 구간당 Sonnet 4회 호출. 전 트랙 일괄이면 사령관에게 규모·순서를 한 번 확인한다(워크플로 사용은 사령관 명시 동의가 있을 때만).

## 1. 기계 검사 먼저 (LLM 0토큰)
토론은 비싸다. 기계가 잡을 것은 기계가 먼저 잡는다.
- 화법: `node tools/voice_check.mjs`
- 겹침: 페이지형(adp·agentlab) `until mkdir /tmp/uicheck.lockdir 2>/dev/null; do sleep 7; done; node tools/ui_check.mjs <파일>; rmdir /tmp/uicheck.lockdir` / 장면형 트랙은 CLAUDE.md §4 렌더 스캔 — ui_check 는 스크립트 오류·슬라이더 조작 중 오류·팝업 안 빈 계산 자리도 잡는다. 교사가 인라인 JS 를 고쳤으면 반드시 다시 돌린다(겹침만 보고 통과시키면 화면이 멈춘 채 배포된다).
- 숫자·참조 훑기: `python3 .claude/skills/learner-teacher-review/sweep.py <파일...>` — 본문 속 소수·퍼센트 리터럴(하드코딩 후보), `§N`·편 번호 참조, 반말 끝맺음, 정의 전 등장 후보를 뽑는다.
- 자료 전용 검사가 있으면 함께(Agent Lab `python3 agentlab/data/verify.py`).
여기서 나온 결함은 토론 전에 고친다(또는 교사 브리프에 넘긴다).

## 2. 학습자 1라운드 — `learner.md` 를 브리프로
- Sonnet(implementer) 1기 per 구간, 병렬. **학습자에게 설계서·교사 결론·Advisor 가설을 주지 않는다**(독립 독자 — 답을 쥔 독자는 막히지 않는다).
- 학습자는 **숫자를 스스로 다시 계산**한다(모듈을 node 로 돌리거나 Python 으로). 화면 값과 다르면 그 자체가 질문이다.
- 산출: 편마다 질문 최대 8개(유형 1~8) + 한 줄 평 → 토론 파일.

## 3. 교사 1라운드 — `teacher.md` 를 브리프로
- 학습자 질문 파일을 받아 질문마다 원문·실제 값 확인 → 보강/배치/기각, 답 2~4문장, 페이지 수정.
- Advisor 는 학습자 질문 중 **숫자 불일치·정답 누설·가정 누락**처럼 결과를 뒤집을 수 있는 것을 가설로 짚어 넘겨도 된다(검증은 교사가 직접).

## 4. 학습자 2라운드 → 교사 최종 — `round2.md`
- 같은 학습자(SendMessage 로 이어서, 맥락 유지)가 교사 답과 `git diff` 를 읽고 `R1 납득 / R1 재질문: 이유`, 새로 생긴 질문은 `R+`.
- 교사가 재질문·R+ 를 한 번 더 판정(T2). **토론은 2라운드에서 끝낸다.** 그래도 남는 것은 Advisor 가 판정.

## 5. Advisor 감사 (교사의 자기 채점 금지)
1. 토론 파일에서 **기각 전부**와 보강 표본을 원문·diff 로 대조한다(기각 이유가 "본문에 있다"면 그 인용이 실제로 있는지).
2. 새로 들어간 숫자 리터럴을 `sweep.py` 로 다시 훑는다(계산값 주입인지, 상수·자료 크기인지).
3. 편 사이 결함(순서·인용·같은 이름 다른 숫자)은 구간 교사들이 "보고만" 한 것을 모아 Advisor 가 한 번에 처리한다.
4. 통합 검증을 **한 번** 돌린다: 자료 검사(verify 등) 전부 통과 · ui_check ✅ · voice 0 · 산출 CSV/모듈 바이트 비교(텍스트만 고쳤다면 불변이어야 함).
5. 통계: 질문 수 · 2라운드 납득 수 · 재질문/R+ 처리 수 · 대표 수정 3~5개 → 사령관 보고. 커밋·범프·push.
