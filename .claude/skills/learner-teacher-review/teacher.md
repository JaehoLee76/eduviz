## 판정
질문마다 원문·실제 값(모듈·CSV·코드 출력)을 직접 확인하고:
- **보강**: 본문이 실제로 막히게 쓰였다 → 고친다.
- **배치**: 답은 있는데 늦게·엉뚱한 곳에 있다 → 순서를 옮기거나 다리 문장.
- **기각**: 이미 제자리에 있다(어디인지 인용) 또는 트랙 범위 밖(선택과 집중).
답은 2~4문장, 존댓말, 기본 용어 위에서 정확하게. 질문 아래에 덧붙임:
`T1 [보강|배치|기각] 답: ... / 고친 곳: §3 둘째 문단 — 무엇을 어떻게(한 줄)`

## 고칠 때
- 문장을 덧대기보다 **순서를 다시 세운다**(막힘 → 이름 → 계산). 곁가지 답은 Q&A 팝업에 보탠다.
- 숫자를 쓰거나 방향("커질수록 ~")을 말할 때는 실제 출력을 확인하고, 하드코딩하지 말고 기존 주입 방식(data-v·계산 함수)을 따른다.
- 결함 하나 = 같은 유형을 맡은 편 전체에서 훑기.
- 용어를 새로 정의하면 용어표·개수 문구도 맞춘다. 개수 검사(예 verify.py)가 있으면 「개수 변경: 편·항목·전→후」를 보고한다.
- 화법: 제작·태도·수정 이력 문구 금지, 인용 밖 "-다." 반말 끝맺음 금지, Q&A 팝업 안 퍼센트 숫자 금지(Agent Lab), 캔버스 11px 이상, 원문자·문자 아래첨자 금지.
- 손대지 않는 것: 데이터 모듈·CSV·시뮬레이터, 코드 블록의 코드와 출력(대조 검사 대상), 「앞으로 기록해 둘 데이터」 항목·「에이전트 도구 상자」 함수 이름, 맡은 파일 밖. 고쳐야 하면 고치지 말고 보고(편 사이 문제도 보고만).
