제조 AI 에이전트 연구소

이 공정, 이 설비를 스스로 모니터링하고 분석해서, 무엇을 왜 검정했고 결론이 무엇인지까지 사람에게 보고하는 전용 AI 에이전트 — 그것을 설계하고, 그 AI가 배울 데이터 자산을 가진 사람이 되는 것.

1왜 이 길인가

범용 도구를 넓게 아는 것보다, 한 공정을 깊게 아는 도구를 갖는 쪽이 이깁니다.

공정 전용 AI가 이깁니다

범용 AI나 범용 자격은 어느 공장에든 맞지만 어느 공장에도 딱 맞지 않습니다. 특정 공정 전용 AI는 쓸 곳이 좁은 대신 비용이 적게 들고, 그 공정에서는 성능이 더 높습니다.

코드는 AI가 짜도 기초는 내 몫입니다

코드는 AI가 대신 써 줄 수 있습니다. 하지만 이론, 수식, 기본 코드를 아는 사람만이 결과가 맞는지 가려낼 수 있고, 그 차이가 결과의 품질을 가릅니다.

쌓인 현장 데이터가 자산입니다

현장 데이터와 분석 사례는 오랜 시간이 걸려야 쌓입니다. 그래서 남이 단기간에 따라올 수 없는 자산이 됩니다.

2다룰 데이터와 업무

세 종류의 데이터가 아래 업무 흐름 곳곳에서 나옵니다.

데이터 1

설비 FDC 시계열

설비가 공정 중에 남기는 센서 값의 시간 기록입니다. FDC는 Fault Detection and Classification, 곧 이상 감지와 분류를 뜻합니다.

데이터 2

PPA 2차원 데이터

PPA(Pixel Position Alignment)는 증착 결과의 위치 정렬 품질입니다. 화면 위 각 지점의 어긋남을 2차원 지도로 얻습니다.

데이터 3

생산 Loss 기록

생산이 계획대로 되지 못한 손실을 항목별로 남긴 기록입니다.

업무 흐름

  1. 1단계증착용 마스크 제작
  2. →
  3. 2단계세정
  4. →
  5. 3단계증착 품질(PPA) 해석
  6. →
  7. 문제가 있으면마스크 리페어: 파손 수리 · PPA 보정 · 세정 후 이물 제거
  8. →
  9. 마지막결과 확인

리페어(repair)는 고쳐 쓰는 일입니다. 고친 뒤에는 PPA를 다시 재서 정말 나아졌는지 확인합니다.

3다섯 기둥

번호는 곧 학습 순서입니다. 각 기둥은 “무엇을 할 수 있게 되는가”로 시작합니다.

1

변경점 전후 유의차 분석

대책을 적용하거나 리페어·세정을 한 전후에 정말 달라졌는지 판정할 수 있게 됩니다.

  • Welch t검정
  • 맨-휘트니 (Mann-Whitney)
  • Levene (산포 변화)
  • 대응표본 검정
  • 효과 크기·신뢰구간
  • 동등성 검정 (TOST)
  • 자기상관·교란 주의
2

가성 인터락을 배제하는 최적 spec

설비를 쓸데없이 세우는 가성 인터락(false interlock, 실제 이상이 아닌데 울리는 정지 신호)은 줄이고 진짜 이상은 놓치지 않는 한계선을 정할 수 있게 됩니다.

  • 궤적→특징
  • 1종·2종 오류
  • 3σ의 세 가정(정규성·독립성·깨끗한 기준)
  • 분위수 한계
  • 로버스트 추정(중앙값·MAD)
  • 다중 비교
  • 평균 런 길이 (ARL)
  • EWMA·CUSUM
  • 드리프트 적응
  • 비용 기반 최적화
3

PPA 2차원 해석

어긋남 지도를 평행이동·회전·배율 같은 큰 성분과 국소 결함으로 갈라, 보정할지 리페어할지 판단할 수 있게 됩니다.

  • 벡터장 (dx, dy)
  • 최소제곱 성분 분해(평행이동·회전·배율·직교도)
  • 잔차 = 국소 결함
  • 반복 위치 = 마스크 기인
  • 리페어 전후 맵 비교
4

보고하는 AI 에이전트

앞의 세 기둥에서 만든 부품을 묶어, 분석하고 보고서까지 쓰는 에이전트를 설계할 수 있게 됩니다.

  • 검증된 함수 = 도구
  • 분석 사례 은행
  • 검정 선택 규칙
  • 과거 사례 검색 (RAG)
  • 보고서 생성
  • 사람 판단과의 일치율로 평가
5

생산 Loss

손실이 어디서 생기는지 분류하고, 어떤 항목이 서로 엮여 있는지 보고, 앞으로의 손실을 예측할 수 있게 됩니다.

  • Loss 분류 체계
  • 파레토 (Pareto)
  • 항목 간 상관(가짜 상관 주의)
  • ML Loss 예측
  • 공정 추적 기반 예측

4에이전트 구조

에이전트(agent)는 스스로 도구를 골라 쓰고 결과를 보고하는 프로그램입니다. 그 부품이 어디서 나오는지 보여 드립니다.

공부하는 과정이 곧 에이전트의 부품을 만드는 과정입니다.

5학습·실행 로드맵

기간은 대략입니다. 일과 병행하며 단계마다 실제로 쓸 수 있는 결과를 하나씩 남깁니다.

  1. 0~3개월

    단계 1 · 기초 다음 단계

    변경점 검정과 궤적→특징을 익히고, 분석 사례 은행에 기록을 시작합니다.

  2. 3~6개월

    단계 2 · 첫 실무 성과

    실제 변경점의 판정을 보고합니다. 가성 인터락을 줄이는 spec을 과거 데이터로 다시 만들어 보며 검증합니다.

  3. 6~12개월

    단계 3 · PPA

    성분 분해로 보정할지 리페어할지 가르는 판단 기준을 만듭니다.

  4. 12~18개월

    단계 4 · 에이전트 시제품

    도구 상자와 사례 검색을 묶어 보고서 초안을 자동으로 씁니다.

  5. 18~24개월

    단계 5 · Loss와 확장

    생산 Loss 분석을 더하고, 다른 설비와 공정으로 넓힙니다.

6실험실 목록

첫 실험실은 기둥 2의 첫 걸음이며, 단계 1에 놓입니다.

궤적에서 특징으로 — FDC 데이터의 모양 다음 단계 기둥 2 · 설비가 남긴 시간 곡선(궤적)에서 최댓값, 기울기 같은 숫자(특징)를 뽑는 법.

7실무 적용 전략

매일 루틴

개념 하나, 함수 하나, 실무 적용 한 건의 기록을 매일 남깁니다.

사례 은행은 첫날부터

엑셀 한 장으로 시작해도 됩니다. 질문, 고른 검정과 이유, 결과, 조치, 사후 결과를 한 줄씩 적습니다.

결과는 숫자 한 장으로

보고는 한 장의 숫자로 끝냅니다. 예를 들면 “가성 인터락 몇 % 감소”, “이상을 몇 시간 먼저 탐지” 같은 꼴입니다. 이 문장은 형식을 보이는 예시이며 실제 수치가 아닙니다.

현장 짝 한 명

현장 엔지니어 한 명과 짝(champion, 함께 성과를 만드는 지지자)을 이뤄 그 설비에서 먼저 성과를 냅니다.

매일 쓰이는 작은 도구로

분석으로 끝내지 않고, 매일 쓰이는 작은 도구로 남깁니다. 쓰이지 않는 분석은 자산이 되지 않습니다.

GPU 없이 시작

이 로드맵의 대부분은 사무용 PC의 CPU로 충분합니다.

데이터 경계

회사 데이터와 분석 사례 은행은 회사 안에서만 다룹니다. 이 사이트의 실험실은 공개 데이터와 가상 데이터만 씁니다.

8콘텐츠 세 종류

학습자료

개념을 이해합니다

검정, 수식, 용어를 읽는 순서대로 풀어 설명한 글입니다.

실험실

직접 계산하고 조작합니다

주어진 데이터를 직접 계산하고 조작하며, Python 코드와 검증된 함수를 함께 얻습니다.

연구실

내 데이터에 적용합니다

자기 데이터에 적용해 기록하는 양식입니다. 내용은 회사 안에서만 보관합니다.
