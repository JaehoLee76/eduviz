닫힌 고리 — 트윈 안에서 판단을 시험하기

결정을 라인에 쓰기 전에 시뮬레이터에서 먼저 시험하려면, 그 시뮬레이터가 지금 공장과 같은지 재고 맞추는 일이 고리로 이어져야 합니다

← 실험실 목록← 이전: Loss 예측

시뮬레이터에서 가장 좋았던 결정이 실제 라인에서도 가장 좋다는 보장은 없습니다. 시뮬레이터가 실제 공장과 어긋나 있으면 그 안에서 고른 결정이 오히려 손해가 됩니다. 그래서 결정을 시험하기 전에 먼저 실제 로그와 시뮬레이터의 차이를 재고, 그 차이가 줄도록 시뮬레이터의 값을 맞추고, 맞춘 시뮬레이터에서 결정을 다시 고르고, 적용한 뒤 실제 결과를 기록해 다시 처음의 차이 재기로 돌아가야 합니다. 이 순환이 이 트랙이 향하는 궁극의 모습입니다. 동시에 이 순환의 부품 가운데 어디까지가 현장에서 검증된 방법이고 어디부터가 아직 연구 단계인지를 알아야 회사에서 헛된 약속을 하지 않습니다. 같은 가상 공장의 일 로그와 세정기 운전 대수 결정 하나로 전부 직접 해 봅니다.

시작하기 전에

이미 아시는 것 — 0206 의 개체·상태·전이·제약(ESTC), 0401 의 에이전트·도구·정책(‘무엇을 보고 어떻게 정하는가’의 규칙)·사람 승인, 0402 의 계획 모델과 실제 전이의 차이(sim-real gap), 0400 의 파이프라인, 0501~0503 의 Loss 파레토·연쇄·예측과 시드마다의 흔들림.

  • 개체·상태·전이·제약 (0206)
  • 정책·사람 승인 (0401)
  • sim-real gap (0402)
  • 파이프라인 (0400)
  • Loss 파레토·예측 (0501~0503)

새로 이름을 붙이는 낱말은 여섯 개입니다. 쓰이는 자리에서 하나씩 정의하고, 정의한 뜻 그대로만 씁니다. 이 여섯 개 말고 계산에 붙인 이름(gap·총 비용·보정 최소점)은 쓰는 자리에서 식이나 문장으로 정의합니다.

  • 디지털 트윈 (digital twin)
  • 트윈 보정 (model calibration)
  • 닫힌 고리 (closed loop)
  • 결정 손해 (decision regret)
  • 검증 영역 (validated envelope)
  • 확립 / 미완 (established / open)

이 실험실에서 가져가는 것

  1. 실무에서 쓰는 곳 — 세정기 운전 대수나 예비 카세트 수 같은 결정을 라인에 쓰기 전에 시뮬레이터에서 먼저 시험하려 할 때, 그 시뮬레이터가 지금 공장과 맞는지부터 재는 습관. 그리고 회사에서 ‘디지털 트윈 과제’를 제안받았을 때 무엇이 이미 되는 일이고 무엇이 아직 연구인지 가르는 판단표(1~7절).
  2. 손으로 연습 — 보정 안 된 시뮬레이터로 결정을 골라 실제 결과로 손해를 재기, 세정 시간 하나를 격자로 맞춰 gap 이 줄어드는 것 보기, 맞춘 시뮬레이터로 다시 골라 손해가 줄어드는지 보기, 확인된 범위 밖으로 결정을 밀 때 무슨 일이 나는지 보기(1~6절).
  3. 다음 날 산출물 — twin_gap·grid_calibrate·policy_sweep·decision_regret·envelope_check Python 함수(10절), 닫힌 고리 점검표(7절), 트윈 결정 검토서 양식(11절).
  4. 기록할 데이터 — 결정마다 그때 고려한 대안·고른 이유·고를 확률, 트윈 판(파라미터 값·보정한 날), 결정 뒤 실제 결과를 같은 키로(11절).
  5. 사람·규칙·에이전트의 몫 — 결정 승인·비용 가정·숨은 변수 의심은 사람, 보정 전 결정 금지·영역 밖 경고·고리 주기는 규칙, gap 감시·격자 보정·결정 표·검토서 초안은 에이전트(8절).
  6. 성과 환산 — 보정 없이 시뮬레이터 권고를 따랐을 때의 결정 손해(장수/월)와 보정 뒤의 손해, 턴 환산(9절).

여기서부터 가상 공장의 기록으로 푸는 풀이입니다

1첫 시도 — 기획이 돌린 시뮬레이터가 말하는 것

결정은 하나입니다. 세정기를 몇 대 돌릴 것인가(운전 대수, 22~34대). 0401 에서 본 정책 가운데 가장 단순한 꼴, 곧 값 하나를 고정해 두는 정책입니다. 지금은 대를 돌립니다. 결정마다 얻는 것과 드는 것을 한 저울에 올리기 위해 총 비용을 이렇게 정의합니다.

총 비용 (장/일) C(c)=l(c)+k·c c 는 운전 대수, l(c) 는 그 대수로 돌렸을 때 하루에 잃는 유리 장수(Loss), k 는 세정기 한 대의 하루 운영비를 유리 장수로 바꾼 값입니다(가정). 가장 작은 C 의 c 가 그 저울에서의 가장 좋은 결정입니다.

기획이 돌린 시뮬레이터는 세정 한 번이 분 걸린다는 지금의 믿음을 그대로 넣은 것이고, 시드 개의 평균으로 l(c) 를 냅니다. 아래에서 k 를 움직여 이 시뮬레이터가 무엇을 권하는지 보십시오.

무엇을 볼지 먼저. k 를 올릴 때 가장 낮은 막대가 어느 쪽으로 옮겨 가는지, 그리고 대와 대의 하루 Loss 가 얼마나 다른지 보십시오.

2막힘 — 이 시뮬레이터는 지금 공장과 같은가

확인할 수 있는 것은 실제 로그뿐입니다. 같은 지표를 실제 로그와 시뮬레이터에서 똑같이 뽑아 나란히 놓습니다. 지표는 결정(세정기 운전 대수)에 직접 닿는 것을 우선해 셋으로 정했습니다 — 세정 대기열의 시간 평균(대), 세정 중인 세정기 수의 시간 평균(대), 기간 안에 시작한 Loss 사건이 잃은 유리 장수의 합. 세정기가 모자라면 대기열이 길어지고, 대기열이 길어지면 마스크가 늦게 돌아와 Loss 가 늘기 때문입니다.

실제 로그와 기획의 시뮬레이터 — 앞 일
무엇을 볼지 먼저. 로그 기간을 줄여도 두 쪽의 차이가 남는지, 실제 쪽 값이 시뮬레이터 시드 여섯 개의 흔들림 폭 안에 드는지 보십시오.
실제 로그의 일별 세정 대기열 평균시뮬레이터 한 시드의 일별 평균위 표가 쓰는 기간

같은 값을 두 쪽에서 재는 일이니 시드를 같게 두면 되겠다는 생각이 들 수 있습니다. 그러지 않습니다. 시뮬레이터 쪽 시드는 실제 로그와 다른 여섯 개를 고정해 씁니다. 3절에서 같은 시드로 견주면 어떻게 되는지 확인합니다.

3이름 — 디지털 트윈과 gap

디지털 트윈(digital twin) 은 실제 라인의 상태와 전이를 따라 움직이도록 만든 시뮬레이터입니다. 이 실험실에서는 simulateLoss 에 지금 믿고 있는 파라미터를 넣은 것이고, 세정 시간을 180분으로 둔 기획의 시뮬레이터가 트윈 판 0 입니다. 트윈이 실제를 얼마나 따라가는지는 0402 에서 sim-real gap 으로 쟀습니다. 여기서는 같은 생각을 결정에 닿는 지표 셋으로 줄여 한 숫자로 만듭니다.

트윈과 실제의 gap gap=13∑k|lnTk+1Rk+1| T 는 트윈의 지표(시드 평균), R 은 실제 로그의 지표, k 는 위 세 지표입니다. 비의 로그를 쓰므로 단위가 다른 지표를 같은 저울에 올릴 수 있고, 값 0 은 완전히 같다는 뜻이며 0.7 이면 한쪽이 다른 쪽의 약 두 배라는 뜻입니다.
트윈 판 0 의 gap (앞 일)

4트윈 보정 — gap 이 줄도록 값을 맞춥니다

gap 이 크다고 시뮬레이터를 버리지는 않습니다. 어긋남이 어느 값에서 오는지 의심되는 곳을 찾아 그 값을 맞춥니다. 2절에서 실제 쪽 세정 대기열이 훨씬 길었으므로 의심되는 값은 세정 시간 하나입니다. 트윈 보정(model calibration) 은 실제 로그와 트윈 출력의 차이가 줄도록 트윈의 파라미터를 맞추는 일입니다. 가장 단순한 방법은 격자입니다 — 세정 시간 후보를 150분부터 260분까지 10분 간격 12개로 두고, 후보마다 트윈을 시드 개로 돌려 gap 을 재어, gap 이 가장 작은 후보를 보정 최소점으로 삼습니다.

0503 의 보정도와는 다른 말입니다. 0503 의 보정도는 예측한 확률이 실제 빈도와 맞는 정도였습니다. 여기서의 트윈 보정은 시뮬레이터의 값을 실제 로그에 맞추는 일입니다.

세정 시간 후보별 gap — 굵은 선이 이 화면의 로그, 연한 선은 다른 로그 시드 열아홉 개
무엇을 볼지 먼저. 로그 기간을 7일로 줄이면 굵은 선의 바닥이 어디로 옮겨 가는지, 연한 선들의 바닥이 얼마나 흩어지는지 보십시오. 후보 간격이 10분이라 보정 최소점은 10분 단위로만 나옵니다.
이 화면의 로그다른 로그 시드 열아홉 개트윈 판 0 (분)
로그 시드 스무 개의 보정 최소점 — 로그가 짧을수록 흩어집니다

아닙니다. 공장이 바뀌기 때문입니다. 세정액이 낡고, PM 으로 설비 상태가 달라지고, 마스크가 늙고, 작업자와 제품이 바뀝니다. 오늘 정밀하게 맞춘 값이 석 달 뒤에도 맞는다는 보장이 없습니다. 그래서 정밀하게 한 번 만드는 일보다 로그로 gap 을 계속 재서 어긋나기 시작하는 때를 알아채는 일이 더 중요합니다. 고리를 도는 이유가 이것입니다.

이 실험실은 의심되는 값 하나를 격자로 맞췄습니다. 값이 여럿이면 격자의 후보 수가 곱으로 늘어나 감당이 안 되고, 더 어려운 문제가 생깁니다. 로그로는 서로 구분되지 않는 값의 쌍이 있을 수 있습니다. 예를 들어 세정이 길어진 것과 세정기로 오는 마스크가 늘어난 것이 같은 대기열 모습을 만들면, 어느 값을 고쳐야 하는지 로그만으로 가릴 수 없습니다. 불확실성까지 함께 내는 방법은 0602 에서 다룹니다. 지금은 한 번에 하나씩, 그리고 고친 값이 다른 지표를 해치지 않는지 gap 표로 확인합니다.

5결정 다시 고르기 — 결정 손해

이제 보정한 트윈(세정 시간을 보정 최소점으로 둔 판)으로 1절의 저울을 다시 올립니다. 두 판이 같은 결정을 권하면 보정은 결정에 영향이 없었던 것이고, 다르게 권하면 어느 쪽이 맞았는지 실제 결과가 가립니다. 그 차이를 이렇게 정의합니다. 결정 손해(decision regret) 는 트윈에서 고른 결정을 실제에 썼을 때, 실제에서 가장 좋았을 결정보다 더 잃는 몫입니다.

결정 손해 (장/일) 손해=C실제(c트윈)−mincC실제(c) C 실제 는 결정을 적용한 뒤 실제에서 잰 총 비용입니다. 트윈이 고른 결정이 실제에서도 가장 좋았다면 0, 아니면 양수입니다.

한 가지 짚어 둡니다. 회사에서는 결정 값 열세 개를 전부 60일씩 돌려 볼 수 없고, 적용한 한 점의 결과만 압니다. 이 가상 공장에서는 결정 값마다 실제 결과를 여덟 번씩 돌려 둔 표가 있어 실제 곡선 전체를 그릴 수 있고, 그래서 트윈 권고의 손해를 잴 수 있습니다. 회사에서는 이 손해를 적용 뒤 한 점씩 쌓아 가며 알게 됩니다. 11절에서 그 기록을 다룹니다.

6검증 영역 — 트윈이 말해 줄 수 있는 범위

보정한 트윈이 권하는 결정이 로그가 한 번도 겪어 본 적 없는 조건이라면 어떻게 합니까. 검증 영역(validated envelope) 은 트윈이 실제와 맞는다고 로그로 확인된 운전 조건의 범위이고, 그 밖으로 나간 결정은 트윈이 말해 주지 못합니다. 이 로그는 세정기 대 운전의 기록이므로, 시간별 ‘세정 중인 세정기 수’의 최소와 최대가 곧 로그가 겪어 본 조건입니다. 결정 값이 그 최소 이상이고 지금 운전 대수 이하이면 영역 안, 아니면 밖으로 봅니다. 운전 대수를 올리는 결정은 로그에 한 번도 나타난 적 없는 조건입니다.

결정 값별 영역 안/밖과, 보정한 트윈의 예측과 실제 결과의 차 (k 와 로그 기간은 5절의 값)
영역 안영역 밖

7닫힌 고리 지도 — 무엇이 확립이고 무엇이 미완인가

지금까지 한 일을 고리로 이으면 닫힌 고리(closed loop) 가 됩니다. 기록 → 트윈 보정 → 트윈 안에서 결정 시험 → 사람 승인 → 실제 적용 → 결과 기록 → 다시 보정으로 이어지는 순환입니다. 아래 표의 마지막 열 이름은 확립 / 미완(established / open) 입니다. 방법이 현장에서 검증된 표준이면 확립, 아직 연구 단계이면 미완입니다.

닫힌 고리 — 고리의 각 부품과 이 트랙의 실험실

번호를 따라 한 바퀴를 돌면 실제 결과가 기록으로 돌아와 다음 보정의 재료가 됩니다. 색이 칠한 부품은 이 실험실에서 직접 해 본 것입니다.

점검표의 마지막 두 줄이 미완이라는 것은, 그 부품을 회사에서 ‘곧 됩니다’라고 약속하면 안 된다는 뜻입니다. 지금 되는 일은 1~5번 부품이고, 그것만으로도 이 실험실의 결정 손해를 줄이는 일이 가능합니다. 이어지는 실험실은 각각 고리의 빈 곳을 채웁니다. 0602 는 값이 여럿일 때의 보정과 불확실성을, 0603 은 턴마다 자동으로 고치는 런투런 제어를, 0604 는 과거 로그만으로 새 규칙의 효과를 미리 추정하는 평가를, 0605 는 보정된 트윈 안에서의 작은 강화학습을, 0606 은 지금 닿을 수 있는 한계선을 다룹니다.

보정된 트윈과 검증 영역이 있은 뒤입니다. 강화학습은 트윈 안에서 결정을 수없이 시험해 좋은 정책을 스스로 찾는 방법이라, 트윈이 어긋나 있으면 그 어긋남을 가장 잘 이용하는 정책을 찾아냅니다. 5절에서 보았듯 어긋난 트윈이 권하는 결정은 이미 손해입니다. 학습이 그 위에서 더 열심히 최적화하면 손해도 더 정교해질 수 있습니다. 그래서 순서는 기록, 보정, 영역 확인, 그다음 학습입니다. 0605 에서 다룹니다.

10Python — 회사 PC에 가져갈 코드

아래 코드는 pandas·numpy 만 씁니다. 입력은 실제 로그(s17_real_events.csv·s17_real_hourly.csv), 트윈 격자 요약 표(s17_twin_grid.csv), 결정 표(s17_policy_table.csv), 시드 요약 표(s17_seed_summary.csv)이고, 코드와 같은 폴더에 두면 그대로 돌아갑니다. 회사에는 시뮬레이터가 없을 수 있으므로 보정과 결정 계산은 요약 표만으로 다시 해 봅니다.

s17_real_events.csvs17_real_hourly.csvs17_twin_grid.csvs17_policy_table.csvs17_seed_summary.csv

쓰면 안 되는 때: 트윈과 실제를 같은 시드로 견주지 마십시오(난수의 순서가 같아져 두 쪽이 독립이라는 전제가 깨지고, gap 이 어느 쪽으로 틀어지는지 알 수 없습니다). 검증 영역 밖의 결정을 트윈의 수치만으로 승인하지 마십시오. 로그 7일로 맞춘 값을 확정값처럼 쓰지 마십시오(4절의 흩어짐). 보정에 쓴 로그와 결정 손해를 재는 로그를 같은 것으로 쓰지 마십시오.

import numpy as np
import pandas as pd

# ---- 가정·설정: 회사 값으로 바꿀 곳 --------------------------------------------------
LOG_DAYS = 60          # 보정에 쓸 실제 로그 기간(일)
COST = 500             # 세정기 한 대의 하루 운영비(유리 장수로 환산, 가정)
CAP_LOGGED = 27        # 로그가 기록된 운전 대수(결정 값)
V0_CLEAN = 180         # 지금 믿고 있는 세정 시간(분) = 트윈 판 0
HORIZON = 60           # 결정 표의 Loss 가 재어진 기간(일)
KEYS = ["q", "busy", "L"]
KO = {"q": "세정 대기열", "busy": "세정 중", "L": "Loss"}

def log_metrics(events, hourly, days):
    """실제 로그의 앞 days 일을 지표 셋으로 줄인다: 세정 대기열 평균·세정 중 평균·Loss 총 장수."""
    h = hourly.iloc[: days * 24]
    ev = events[events["start_min"] < days * 1440]
    return {"q": h["cleaner_queue"].mean(), "busy": h["cleaner_busy"].mean(), "L": ev["loss_glass"].sum()}

def twin_gap(real, twin):
    """트윈과 실제의 gap: 지표마다 |ln((트윈+1)/(실제+1))| 를 구해 평균한다."""
    parts = {k: abs(np.log((twin[k] + 1) / (real[k] + 1))) for k in KEYS}
    return float(np.mean(list(parts.values()))), parts

def grid_calibrate(grid, real, days):
    """세정 시간 격자마다 트윈 시드 평균 지표로 gap 을 재고, 가장 작은 곳(같으면 짧은 쪽)을 고른다."""
    g = grid[grid["days"] == days].groupby("clean")[KEYS].mean()
    gaps = pd.Series({c: twin_gap(real, g.loc[c])[0] for c in g.index})
    return int(gaps.idxmin()), gaps, g

def policy_sweep(pol, side, clean, cost):
    """결정 값(세정기 운전 대수)마다 하루 Loss 와 총 비용(= 하루 Loss + 운전 대수 × 한 대 비용)."""
    p = pol[pol["side"] == side]
    if side == "twin":
        p = p[p["clean"] == clean]
    day_loss = p.groupby("cap")["loss"].mean() / HORIZON
    return pd.DataFrame({"loss": day_loss, "cost": day_loss + cost * day_loss.index})

def decision_regret(pol, choice, cost):
    """고른 결정을 실제에 썼을 때, 실제에서 가장 좋았을 결정보다 더 잃는 몫(장/일)."""
    sw = policy_sweep(pol, "real", None, cost)
    best = int(sw["cost"].idxmin())
    return best, float(sw.loc[choice, "cost"] - sw.loc[best, "cost"])

def envelope_check(hourly, decision):
    """결정 값이 로그에서 확인된 운전 조건(세정 중 대수의 최소~최대, 쓴 운전 대수) 안인가."""
    lo, hi = int(hourly["cleaner_busy"].min()), int(hourly["cleaner_busy"].max())
    return lo, hi, bool(lo <= decision <= CAP_LOGGED)

if __name__ == "__main__":
    events = pd.read_csv("s17_real_events.csv")
    hourly = pd.read_csv("s17_real_hourly.csv")
    grid = pd.read_csv("s17_twin_grid.csv")
    pol = pd.read_csv("s17_policy_table.csv")
    summ = pd.read_csv("s17_seed_summary.csv")

    real = log_metrics(events, hourly, LOG_DAYS)
    print("실제 로그 %d일 · 사건 %s건 · 시간별 %s줄 · 운전 대수 %d" % (LOG_DAYS, format(len(events), ","), format(len(hourly), ","), CAP_LOGGED))
    print("실제 로그 지표: 세정 대기열 평균 %.2f대 · 세정 중 평균 %.2f대 · Loss 총 %s장" % (real["q"], real["busy"], format(int(round(real["L"])), ",")))
    best, gaps, g = grid_calibrate(grid, real, LOG_DAYS)
    tw0 = g.loc[V0_CLEAN]
    gap0, parts0 = twin_gap(real, tw0)
    print("트윈 판 0(세정 %d분, 시드 %d개 평균): 세정 대기열 %.2f대 · 세정 중 %.2f대 · Loss %s장" % (V0_CLEAN, grid[grid["clean"] == V0_CLEAN]["seed"].nunique(), tw0["q"], tw0["busy"], format(int(round(tw0["L"])), ",")))
    print("gap 판 0: %.3f (%s)" % (gap0, " · ".join("%s %.3f" % (KO[k], parts0[k]) for k in KEYS)))
    print("격자 보정(로그 %d일): 최소점 %d분 · gap %.3f(판 0 대비 %+.0f%%)" % (LOG_DAYS, best, gaps[best], 100 * (gaps[best] / gap0 - 1)))
    print("로그 기간별 보정 최소점: " + " · ".join("%d일 %d분" % (d, grid_calibrate(grid, log_metrics(events, hourly, d), d)[0]) for d in (7, 14, 30, 60)))

    c0 = int(policy_sweep(pol, "twin", V0_CLEAN, COST)["cost"].idxmin())
    c1 = int(policy_sweep(pol, "twin", best, COST)["cost"].idxmin())
    b0, r0 = decision_regret(pol, c0, COST)
    b1, r1 = decision_regret(pol, c1, COST)
    print("비용 가정 %d장/일: 판 0 권고 %d대 · 보정 뒤 권고 %d대 · 실제 결과로 가장 좋았던 %d대" % (COST, c0, c1, b0))
    print("결정 손해(장/일): 판 0 권고 %.0f · 보정 뒤 권고 %.0f · 월 환산 %s장 → %s장" % (r0, r1, format(int(round(30 * r0)), ","), format(int(round(30 * r1)), ",")))
    for name, c in (("판 0 권고", c0), ("보정 뒤 권고", c1)):
        lo, hi, ok = envelope_check(hourly, c)
        print("검증 영역(%s %d대): 로그의 세정 중 대수 %d~%d · 운전 대수 %d → %s" % (name, c, lo, hi, CAP_LOGGED, "안" if ok else "밖"))

    s = summ[summ["days"] == LOG_DAYS]
    q = lambda col: np.percentile(s[col], [10, 50, 90])
    print("시드 %d개(로그 %d일): 보정 최소점 10·50·90%% %d/%d/%d분 · gap 중앙값 %.3f → %.3f" % (len(s), LOG_DAYS, *q("chat"), s["gap_before"].median(), s["gap_after"].median()))
    print("시드 %d개: 결정 손해 중앙값 판 0 %.0f → 보정 뒤 %.0f (장/일) · 보정 뒤가 더 작은 시드 %d개 · 같은 시드 %d개" % (len(s), s["regret_v0"].median(), s["regret_cal"].median(), (s["regret_cal"] < s["regret_v0"] - 1e-9).sum(), (abs(s["regret_cal"] - s["regret_v0"]) <= 1e-9).sum()))
