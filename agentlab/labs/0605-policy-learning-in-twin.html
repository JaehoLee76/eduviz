트윈 안에서 정책 학습 — 작은 강화학습과 도메인 무작위화

‘지금 바꿀까, 기다릴까’를 칸마다 정한 표를 트윈 안에서 스스로 찾게 하고, 그 표가 트윈이 틀렸을 때 실제에서 얼마나 망가지는지, 그리고 그럴 법한 트윈 여러 개에서 섞어 배우면 얼마나 막아지는지 재어 봅니다

0604 는 이미 정해진 규칙을 로그로 평가했습니다. 이 실험실은 평가할 규칙을 사람이 하나씩 만들지 않고, 트윈(0601 의 시뮬레이터) 안에서 규칙 자체를 학습시킵니다. 예는 조기 잡 체인지 시점입니다. 다음 마스크 세트가 세정기에서 늦게 올 때, 블록이 서 버리기 전에 대기 중인 다른 세트로 먼저 바꿀지, 끝까지 기다릴지를 정합니다. 한 번 정하는 것이 아니라 하루에도 여러 번 반복되는 결정이므로, 상태마다 무엇을 할지 적은 표(정책)가 필요합니다. 이 표를 트윈 안에서 찾고, 트윈이 실제와 어긋나 있을 때 표가 얼마나 상하는지 재고, 0602 의 사후분포로 그 상함을 줄일 수 있는지 확인합니다.

이 실험실의 환경은 학습용 작은 모형입니다. 이 트랙의 가상 공장 시뮬레이터(simulateLoss)는 세트를 언제 바꿀지를 바깥에서 정해 줄 수 없어서, 이 결정을 그 안에서 바꿔 돌릴 수는 없습니다. 그래서 한 판의 구조(상태·행동·잃는 장수)는 이 실험실을 위해 따로 정한 작은 이산 사건 모형이고, 시뮬레이터에서 가져오는 것은 한 가지뿐입니다. 세정 시간이 길어지면 세정기 앞에서 줄 서는 시간이 얼마나 길어지는지(세정 대기열 기록)를 이용해 다음 세트가 도착하는 시각을 정합니다. 교체 비용 같은 숫자는 가정이며 슬라이더로 바꿔 봅니다. 모형이 작아서 학습 결과를 손으로도 검산할 수 있다는 것이 이 선택의 이유입니다.

시작하기 전에

이미 아시는 것 — 0206 의 상태와 전이(지금 어떤 상태이고 행동하면 어떤 상태로 가는가), 0401 의 정책(상황을 보고 행동을 고르는 규칙)과 사람 승인, 0402·0601 의 sim-real gap(트윈 출력과 실제 기록의 차)과 검증 영역(트윈이 맞다고 확인된 운전 범위), 0602 의 사후분포(맞춘 값을 한 숫자가 아니라 가능한 값들의 분포로 낸 것), 0604 의 ε(로그를 만드는 규칙이 일부러 벗어나는 확률의 기준 크기)와 기록 정책·평가.

새로 이름을 붙이는 낱말은 여섯 개입니다. 쓰이는 자리에서 하나씩 정의하고, 정의한 뜻 그대로만 씁니다. 이 여섯 개 말고 계산에 붙인 이름(판·간격·굶음·막힘·학습률 α·리틀의 법칙·지수분포·에를랑 분포)은 쓰는 자리에서 문장이나 식으로 정의합니다.

  • 강화학습 (reinforcement learning)
  • 보상 (reward)
  • 가치 함수 Q (action-value)
  • 탐색 / 활용 (exploration / exploitation)
  • 도메인 무작위화 (domain randomization)
  • 시뮬-실제 전이 손실 (sim-to-real loss)

이 실험실에서 가져가는 것

  1. 실무에서 쓰는 곳 — 조기 잡 체인지 시점처럼 ‘지금 바꿀까, 기다릴까’를 반복해서 정하는 결정에 대해 트윈 안에서 규칙을 학습시키고, 그 결과를 실행이 아니라 사람이 승인할 권고 표로 바꾸는 것, 그리고 트윈이 틀렸을 때 학습된 규칙이 얼마나 망가지는지 아는 것(1~9절).
  2. 손으로 연습 — 손으로 문턱 하나를 정해 트윈과 실제에서 견주기(2절), Q 한 칸을 손으로 갱신하기(3절), 학습 횟수·학습률·탐색률을 바꿔 학습 곡선 보기(4절), 학습된 정책 표를 사람 말로 읽기(5절), 한 값의 트윈에서 학습한 정책과 사후분포에서 뽑은 여러 트윈에서 학습한 정책을 실제에서 견주기(6~7절), 보상(교체 비용)을 바꿔 정책이 바뀌는 것 보기(8절).
  3. 다음 날 산출물 — tabular_q·policy_table·evaluate_policy·randomized_training Python 함수(11절)와 학습 정책 승인 요청서 양식(12절).
  4. 기록할 데이터 — 결정 시점의 상태(남은 유리·경과 또는 대기)와 결정·결과를 같은 키로, 세트 요청·세정 시작·도착 시각을 판마다(12절). 0604 의 결정 기록과 같은 형식의 트윈 판입니다.
  5. 사람·규칙·에이전트의 몫 — 보상(비용)과 승인은 사람, 학습한 적 없는 상태에서는 지금 규칙으로 되돌리는 것은 규칙, 학습·평가·승인 요청서 초안은 에이전트(9절).
  6. 성과 환산 — 지금 규칙 대비 학습 정책이 줄이는 Loss(장수·블록-턴, 월 환산)를 교체 비용 가정과 함께(10절).

1한 판의 구조 — 상태·행동·잃는 장수

블록 하나가 지금 마스크 세트로 증착하는 중이고, 다음 세트는 세정기에서 씻는 중입니다. 판단은 30분마다 합니다. 이 30분을 간격이라 부르겠습니다. 지금 세트의 계획 유리는 간격 단위로 남은 유리 r 만큼(0~) 남아 있고, 한 간격에 한 칸씩 줄어듭니다. 한 판은 다음 세트를 씻기 시작하는 순간에 시작해, 블록이 세트를 바꾸는 순간에 끝납니다. 이 실험실에서 ‘판’은 이 한 번의 과정을 뜻합니다. 0601 의 ‘트윈 판 0’의 판은 트윈의 버전이라는 뜻이어서 다른 말입니다. 판이 시작될 때 r 은 ~ 사이의 정수 가운데 같은 확률로 정해집니다(가정).

판의 어느 순간인지는 두 가지로 적습니다. 하나는 남은 유리 r 이고, 다른 하나는 다음 세트가 아직 안 왔으면 시작부터 지난 간격 수 k, 이미 왔으면 온 뒤 기다린 간격 수 w 입니다. 이 둘이 이 모형의 상태(0206)입니다. 칸 수는 남은 유리 가지 × 도착 상태 가지 = 칸입니다. 각 상태에서 고르는 행동은 둘입니다. 기다림, 또는 지금 교체(조기 잡 체인지). 판이 끝날 때까지 잃은 유리 장수의 합이 그 판의 Loss 입니다.

굶음은 블록이 서 있어서 잃는 장수, 막힘은 이미 도착한 세트가 기다리며 생기는 장수, 교체는 세트를 바꾸는 데 드는 장수입니다. 도착 전에 대기 중인 다른 세트로 바꾸면, 나중에 다음 세트로 한 번 더 바꾸어야 하고(남은 유리가 있었다면 그 세트를 마저 쓰려고 또 한 번), 그만큼 교체 비용이 늘어납니다. 블록이 한 간격 서 있을 때 잃는 장은 챔버 개가 30분 동안 만드는 유리 장수이고, 교체 한 번을 한 간격 서는 값(장)으로 둔 것입니다. 이 가상 공장의 60일 기록에도 같은 자리의 사건이 있습니다. 블록이 다음 세트를 기다려 선 사건(세정기 capa 부족, CL-CAPA)이 건·평균 장, 조기 잡 체인지(JC-EARLY)가 건·평균 장이어서 위 비용과 같은 자릿수입니다.

다음 세트가 오는 시각은 세정 시간이 정합니다. 세트가 올 때까지 걸리는 시간은 세정기 앞에서 줄 서는 시간 + 세정 시간 + 반송(분, 고정)입니다. 줄 서는 시간은 세정기가 꽉 찰수록 급격히 길어집니다. 평균 줄 서는 시간은 리틀의 법칙(Little’s law)으로 잽니다. 줄에 서 있는 평균 수는 줄에 드는 속도에 줄에서 보내는 평균 시간을 곱한 것과 같다는 법칙이고, 거꾸로 쓰면 평균 시간 = 평균 줄 길이 ÷ 줄이 빠지는 속도입니다. 여기서 평균 줄 길이는 세정 대기열 평균 q 이고, 세정 중인 세정기 b 대가 세정 시간마다 하나씩 끝내므로 줄이 빠지는 속도는 b ÷ 세정 시간입니다. 그래서 줄 서는 평균 시간 = q × 세정 시간 ÷ b 입니다. 판마다 실제 줄 서는 시간은 이 평균을 가운데 둔 흔들림으로 둡니다. 지수분포는 짧은 기다림은 흔하고 긴 기다림은 드문, 평균 하나로 정해지는 분포이고, 같은 평균의 지수분포에서 두 번 뽑아 그 평균을 취한 값이 에를랑 분포입니다(한 번 뽑을 때보다 평균 근처에 모입니다). 아래 슬라이더로 트윈의 세정 시간을 바꾸면 도착 시각이 어떻게 달라지는지 보십시오.

막힘: 위 규칙은 ‘남은 유리 0 이고 아직 안 온’ 상태 한 줄만 다룹니다. 이 모형의 상태는 칸이고 도착한 뒤의 상태(남은 유리가 많은데 이미 기다린 세트가 있을 때 바꿀지)도 있습니다. 이 모형은 작아서, 실제 판 기록을 보고 고른 문턱 하나(τ 를 크게 잡으면 남은 유리가 0 이 되자마자 바로 교체하는 규칙입니다)가 학습한 표와 거의 같은 성적을 냅니다(9절 끝에서 숫자로 견줍니다). 그러니 이 모형에서 표 학습이 성적을 더 올려 주지는 않습니다. 표 학습의 쓸모는 다른 데 있습니다. 규칙을 미리 몰라도 트윈 안에서 표가 그 교체 규칙을 스스로 찾아냈다는 확인이고, 문턱은 실제 판 기록을 보고 골랐지만 학습은 트윈만으로 표를 얻고 전이 손실로 점검할 수 있다는 점이며, 상태가 커져 손으로 문턱을 정할 수 없을 때를 위한 연습입니다. 그러나 상태가 커지면 칸마다 손으로 문턱을 정하기 위해 비용의 모든 조합을 사람이 계산해야 하고, 위에서 보았듯 트윈의 도착 분포가 실제와 다르면 트윈에서 고른 문턱이 실제에서 틀립니다. 이 실험실이 보려는 것은 칸마다 ‘여기서 이 행동을 하면 끝까지 얼마나 잃는가’를 스스로 적어 가는 방법과, 트윈이 틀렸을 때 그 표가 얼마나 상하고 어떻게 막는가입니다. 다음 절에서 그 방법에 이름을 붙입니다.

3이름 — 강화학습·보상·가치 함수 Q·탐색과 활용

트윈 안에서 판을 수천 번 겪게 하면서, 상태에서 행동을 고르고 그 결과로 정책을 고쳐 가는 학습을 강화학습(reinforcement learning)이라 합니다. 한 번 행동한 뒤 받는 점수를 보상(reward)이라 하며, 여기서는 그 한 번에 잃은 장수에 마이너스를 붙인 값입니다. 보상이 0 에 가까울수록(덜 잃을수록) 좋습니다.

보상: 한 번의 행동 뒤 받는 점수 r=−(굶음+막힘+교체) 세 항은 1절 표의 값입니다. 판이 끝날 때까지 보상을 더한 값이 그 판의 Loss 에 마이너스를 붙인 것입니다.

칸마다 적어 가는 값이 가치 함수 Q(action-value)입니다. Q(s, a) 는 ‘상태 s 에서 행동 a 를 하고, 그 뒤에는 지금 가장 좋아 보이는 행동을 따랐을 때 판이 끝날 때까지 받을 보상의 합의 기댓값’입니다. 처음에는 모든 칸이 0 이고, 경험할 때마다 아래 식으로 한 칸씩 고쳐 갑니다. 판이 반드시 끝나므로 먼 미래를 깎지 않습니다(γ = 1). α 는 학습률로, 새로 겪은 결과를 기존 값에 얼마나 섞을지 정하는 0 과 1 사이의 수입니다.

가치 함수 Q 의 갱신 Q(s,a)←Q(s,a)+α[r+γmaxa′Q(s′,a′)−Q(s,a)] s′ 는 행동 뒤에 간 다음 상태, a′ 는 그 상태에서 고를 수 있는 행동입니다. 대괄호 안이 ‘방금 겪은 결과(보상 + 다음 상태의 가장 좋아 보이는 값)와 지금 적어 둔 값의 차’입니다. 그 차만큼(α 의 몫) 옮기면 정답에 가까워지는 까닭은, 정답은 ‘이 칸의 값 = 이번 보상 + 다음 칸의 값’이라는 관계를 늘 만족하는 값이고, 그 차는 지금 적어 둔 값이 그 관계에서 얼마나 벗어났는지를 재기 때문입니다. 겪을 때마다 벗어난 몫의 일부씩 고치면 값이 그 관계에 맞는 쪽으로 모이고, α 가 작을수록 한 번의 우연에 덜 끌립니다. 수렴의 엄밀한 증명은 이 트랙에서 다루지 않고, 아래 슬라이더와 4절의 학습 곡선이 실제로 그렇게 움직이는지를 보여 줍니다. 판이 거기서 끝났으면 다음 상태가 없으니 r 만 씁니다.

정책은 칸마다 Q 가 더 큰 행동을 고르는 표입니다. 그런데 아직 덜 해 본 행동은 Q 가 틀려 있을 수 있으니, 가끔은 일부러 다른 행동을 해 봐야 합니다. 가장 좋아 보이는 행동을 하는 것이 활용(exploitation), 덜 해 본 행동을 해 보는 것이 탐색(exploration)입니다. 이 실험실은 확률 ε 로 탐색하고 나머지는 활용합니다(ε-탐욕). 여기서 ε 는 ‘두 행동 가운데 하나를 같은 확률로 무작위로 고르는’ 판단의 비율입니다. 무작위로 고른 행동이 가장 좋아 보이는 쪽과 같을 수도 있으므로, 실제로 가장 좋아 보이는 행동에서 벗어나는 확률은 ε 의 절반입니다. 0604 의 ε 는 상황마다 다른 벗어날 확률의 기준 크기이고, 0606 의 1절도 이 차이를 다룹니다. 또 0604 에서는 로그에 다양성을 남기려고 섞은 것이고 여기서는 Q 가 틀려 있을 칸을 겪어 보려고 섞습니다. Q 가 처음에 0 이고 보상이 모두 0 이하이므로, 해 본 적 없는 행동은 ‘0 점’으로 가장 좋아 보여 탐색이 저절로 일어난다는 점도 기억해 두십시오.

6트윈 판 0 에서 배운 정책을 실제에 — 시뮬-실제 전이 손실

트윈 판 0(세정 시간 분)은 0601 에서 보았듯 실제와 어긋나 있습니다. 거기서 배운 정책을 트윈 안에서 재면 좋아 보이지만, 같은 정책을 실제에 쓰면 다를 수 있습니다. 같은 정책의 트윈 안 성적과 실제 성적의 차를 시뮬-실제 전이 손실(sim-to-real loss)이라 하겠습니다. 0402·0601 의 sim-real gap 이 트윈 출력과 실제 기록의 차였다면, 이것은 그 차가 정책의 성적에 미치는 영향입니다. V 는 판당 평균 Loss 입니다.

시뮬-실제 전이 손실 Δ(π)=V실제(π)−V트윈(π) Δ 가 0 에 가까우면 트윈 안에서 본 성적을 실제에서도 기대해도 됩니다. 양수로 크면 트윈이 정책을 과하게 좋게 보여 준 것입니다. Δ 가 크다는 것은 트윈 안의 성적을 믿지 말라는 신호이지 정책이 나쁘다는 뜻은 아닙니다. 승인 여부는 실제 판 기록에 다시 돌려 잰 성적(과 그 시드 분포), 학습한 적 적은 칸에서 지금 규칙으로 되돌리는지, 사람이 상식으로 읽은 표로 정하고, 9절이 그 숫자를 모읍니다. 이 환경에서는 지금 규칙이 워낙 비싸서 어긋난 트윈에서 배운 정책도 지금 규칙보다 낫지만, 그것이 어긋난 트윈을 써도 된다는 뜻은 아닙니다.

7도메인 무작위화 — 그럴 법한 트윈 여러 개에서 섞어 배웁니다

한 값의 트윈에서 배우면 그 값의 오차까지 배웁니다. 이 예에서는 60일 로그가 길어 사후분포가 좁아서 무작위화가 별로 필요 없어 보입니다. 이 절의 가르침은 ‘로그가 길면 필요 없고, 로그가 짧거나 없을 때 필요하다’이며, 그 차이는 아래 슬라이더로 로그 기간을 줄여 보면 보입니다. 또 사후분포가 담는 불확실성은 세정 시간 하나뿐이어서, 판의 구조나 비용 같은 모형 자체의 오류는 사후분포를 넓게 뽑아도 막지 못합니다. 0602 는 세정 시간을 한 숫자가 아니라 로그에서 가능한 값들의 사후분포로 냈습니다. 그 분포에서 판마다 세정 시간을 새로 뽑아 학습하면 정책은 그럴 법한 트윈 여럿에서 두루 통하는 표를 배웁니다. 학습할 때 트윈의 파라미터를 분포에서 매번 뽑아 바꿔, 특정 한 판에 과하게 맞지 않게 하는 것을 도메인 무작위화(domain randomization)라 부릅니다. 비교할 방식은 셋입니다. 0601 의 격자 보정으로 맞춘 한 값, 0602 사후분포의 평균 한 값, 0602 사후분포 전체에서 판마다 뽑기. 아래 슬라이더는 이 비교를 로그 기간별로 보여 주며, 슬라이더의 마지막 눈금은 로그가 아직 없어 사전(180±분)만 아는 때입니다.

무엇을 볼지 먼저. 로그가 길어 사후분포가 좁을 때는 사후분포 무작위화와 사후 평균 한 값이 거의 같아지는지, 로그 기간을 줄이거나 로그가 없을 때 차이가 얼마나 벌어지는지 보십시오. 시드마다의 흔들림과 견주어 차가 구별되는지도 보십시오.

8보상은 사람이 정합니다 — 교체 비용을 바꾸면 정책이 바뀝니다

학습은 보상이 시키는 대로 정책을 만듭니다. 교체 한 번의 비용을 아주 크게 두면 서 있는 편이 낫다고 보아 끝까지 기다리는 쪽으로 정책이 기웁니다. 그 비용은 데이터가 정해 주지 않습니다. 현장에서 교체 한 번이 실제로 얼마나 잃게 하는지를 사람이 정해 적어야 합니다. 아래에서 교체 비용을 움직이면 같은 학습(사후분포 무작위화)이 어떤 정책을 내는지 봅니다. 두 가지를 겹쳐 봅니다. 가정한 비용으로 학습하고 그 비용이 진짜일 때의 Loss, 그리고 가정이 틀려 진짜 비용은 장인데 다른 값으로 학습했을 때의 Loss 입니다.

교체 비용 가정에 따른 정책과 실제 Loss
무엇을 볼지 먼저. 비용을 올려 갈 때 정책(먼저 바꾸는 판의 몫)이 거의 바뀌지 않는 구간과 바뀌기 시작하는 구간이 어디인지, 비용을 잘못 가정하고 학습한 정책을 진짜 비용으로 재면 Loss 가 얼마나 달라지는지 보십시오.
그 비용이 진짜일 때의 Loss (같은 비용으로 학습·평가)그 비용으로 학습했는데 진짜 비용은 기본값일 때의 Loss
보상을 바꿔 원하는 정책이 나오게 하지 마십시오. 교체 비용을 일부러 낮춰 ‘많이 바꾸는’ 정책을 얻는 것은 근거를 거꾸로 쓰는 일입니다. 비용은 현장의 실제 손실에서 정하고, 정한 근거(어떤 사건 몇 건의 평균인지)를 승인 요청서에 적어 둡니다.

사람이 정합니다. 그리고 보상이 곧 ‘무엇을 좋은 결과로 볼 것인가’입니다. 이 장에서는 잃은 유리 장수를 그대로 보상으로 삼아 정했지만, 현장에서는 Loss 에 단가를 곱하거나 납기 지연 같은 다른 손실을 더할 수 있습니다. 어떤 항을 넣고 빼느냐에 따라 정책이 달라지므로, 보상식은 승인 요청서의 첫 칸에 적고 검토자가 읽도록 합니다. 에이전트가 보상을 스스로 바꾸게 두지 마십시오.

9착지 — 처음 물음에 숫자로 답합니다

맨 앞의 물음으로 돌아옵니다. “조기 잡 체인지 규칙을 트윈 안에서 학습시키면, 실제 라인에서 지금 규칙보다 판당 몇 장을 덜 잃습니까?” 기본 학습 설정과 교체 비용 장으로 답합니다.

이 답이 기대는 것. 1) 다음 세트가 오는 시각이 우리가 무엇을 고르든 달라지지 않는다는 것(이 모형에서는 세정기 앞 줄이 우리 결정과 무관하다고 둡니다). 2) 판의 구조(비용·남은 유리의 범위)가 실제 라인의 판과 비슷하다는 것. 3) 사후분포(또는 보정)가 실제 세정 시간을 포함한다는 것. 이 셋 중 하나라도 어긋나면 위 숫자는 승인 근거가 되지 못합니다. 또 이 모형은 문턱 하나로도 거의 같은 성적이 나올 만큼 단순해서(2절), 여기서 배운 것은 ‘표를 칸마다 스스로 채우는 방법’과 ‘트윈이 틀렸을 때 그 표를 어떻게 점검하는가’이지 이 모형의 규칙 자체가 아닙니다.

사람

  • 보상(교체 비용·굶음 손실)의 값과 근거를 정합니다
  • 정책 표의 사람 말 요약이 상식과 맞는지 읽고, 라인에 적용할지 승인합니다
  • 트윈·사후분포가 아직 맞는 시기인지(공장이 바뀌었는지) 판단합니다

규칙

  • 학습한 적이 적은 상태(검증 영역 밖)에서는 지금 규칙으로 되돌립니다
  • 학습 정책은 실행이 아니라 권고만 냅니다(0401 의 승인 대기열)
  • 사후분포가 로그 기간·보정 날짜가 오래되면 학습을 다시 하라고 알립니다

에이전트

  • 트윈 판·사후분포에서 학습하고 정책 표와 실제 추정 성적(시드 분포)을 계산합니다
  • 학습 곡선·미학습 칸·전이 손실을 승인 요청서 초안에 채웁니다(사실 목록 방식, 0411)
  • 판 기록의 빠진 칸(도착 시각 등)을 감시합니다

0606 으로 가는 다리. 이 장은 트윈이 있다는 전제에서 정책을 배웠습니다. 트윈이 없거나 믿을 수 없을 때 쌓인 로그만으로 정책을 배우려면 어떤 함정이 있는지가 다음 질문입니다.

10현장에서 환산하면

이 환경의 한 판은 ‘다음 세트가 늦어 블록이 서게 될지도 모르는 한 번의 기회’입니다. 가상 공장 60일 기록에서 블록이 다음 세트를 기다려 선 사건(CL-CAPA)이 건이므로 한 달에 약 건이라 보고, 아래 슬라이더의 기본값으로 둡니다(가정). 판당 Loss 의 차에 한 달 판 수를 곱하면 줄어드는 장수입니다. 블록 하나가 한 턴(챔버 개 × 한 챔버 장 = 장)에 만드는 유리 수로 나누면 블록-턴으로도 읽힙니다.

지금 규칙 대비 학습 정책이 줄이는 Loss (실제 판 기록, 학습 시드 개 중앙값)

이 값은 가상 공장의 장수입니다. 회사에서는 같은 식에 유리 한 장의 생산 손실 단가를 곱해 금액으로 적고, 한 달에 세트가 늦는 판 수는 회사의 기록(세트 요청 시각과 도착 시각)에서 셉니다. 이 모형의 ‘판’은 다음 세트가 늦는 때만 모은 것이어서 거의 모든 판에서 블록이 서게 되고, 그래서 판당 Loss 가 큽니다. 판당 Loss 는 60일 기록에서 센 사건 한 건의 평균 장수와 같은 자릿수이고, 월 환산의 크기는 그런 판이 한 달에 몇 번인지(기록에서 센 사건 수에서 가져온 가정)가 정합니다. 교체 비용 슬라이더는 8절과 같은 값입니다. 가정한 비용이 진짜 비용이라는 전제로 학습하고 같은 비용으로 잰 값이므로, 비용을 올리면 지금 규칙의 Loss 도 함께 올라갑니다.

11Python — 회사 PC에 가져갈 코드

아래 코드는 표준 라이브러리(csv·math)만 씁니다. 입력은 아래 CSV 다섯 개이고 코드와 같은 폴더에 두면 그대로 돌아갑니다. 회사에서는 s21_wait_table.csv 자리에 회사의 세정 시간별 줄 서는 시간, s21_real_episodes.csv 자리에 회사의 세트 교체 기록(그때 남은 유리·다음 세트가 도착한 간격 수), s21_posterior.csv 와 s21_twins.csv 자리에 회사의 보정 결과를 넣습니다.

s21_wait_table.csvs21_posterior.csvs21_twins.csvs21_real_episodes.csvs21_seed_summary.csv

쓰면 안 되는 때: 학습한 적이 적은 상태(min_visits 미만)의 학습 결과를 그대로 쓰지 마십시오(policy_table 이 지금 규칙으로 되돌립니다). 트윈 안 성적만으로 승인하지 마십시오(evaluate_policy 에 실제 판 기록을 넣어 전이 손실을 보십시오). 보상(비용)을 바꿔 원하는 정책이 나오게 하지 마십시오. 도착 시각이 우리 결정에 영향을 받는 상황(예: 우리가 먼저 보낸 세트가 세정기 줄을 바꿀 때)에는 이 모형의 지난 판 다시 돌리기가 맞지 않습니다.

import csv
import math

# ---- 가정·설정: 회사 값으로 바꿀 곳 ------------------------------------------------------------------
EP, TR = 30, 20                 # 판단 간격(분) · 세정이 끝난 뒤 반송에 걸리는 분
R_LO, R_HI = 3, 12              # 판이 시작할 때 지금 세트의 남은 유리(간격 수)의 범위
KMAX, WMAX, RMAX = 23, 5, 12    # 상태 칸: 도착 전 경과 0..23 · 도착 뒤 대기 0..5 · 남은 유리 0..12
NS = KMAX + 1 + WMAX + 1        # 남은 유리 값 하나당 도착 상태 칸 수
NSTATE = (RMAX + 1) * NS
DMAX = 60                       # 도착 간격 수 상한
IDLE, CSW, HOLD = 48.0, 48.0, 6.0   # 블록이 한 간격 서는 손실 · 교체 한 번 · 도착한 세트가 기다릴 때 간격당 단위(장)
ALPHA, EPS, EPISODES, MINV = 0.05, 0.1, 4000, 10   # 학습률 · 탐색률 · 학습 판 수 · 학습했다고 보는 최소 방문 수
N_EVAL = 4000                   # 트윈 안 평가에 쓰는 고정 판 수
N_SEEDS = 20                    # 이 코드가 도는 학습 시드 수(시드 1..N_SEEDS)

# ---- 난수: 시드만 쓰는 고정 난수열(FNV-1a 해시 + mulberry32) ------------------------------------------------
M32 = 0xFFFFFFFF
def imul(a, b): return (a * b) & M32
def hash_seed(*parts):
    h = 2166136261
    for ch in "|".join(str(p) for p in parts): h = imul(h ^ ord(ch), 16777619)
    return h
class Rng:
    def __init__(self, seed): self.a = seed & M32
    def u(self):
        self.a = (self.a + 0x6D2B79F5) & M32; a = self.a
        t = imul(a ^ (a >> 15), 1 | a); t = ((t + imul(t ^ (t >> 7), 61 | t)) & M32) ^ t
        return ((t ^ (t >> 14)) & M32) / 4294967296
    def int(self, n): return math.floor(self.u() * n)
    def exp(self, mean): return -mean * math.log(1 - self.u())

# ---- 입력 표 읽기(같은 폴더의 CSV) ---------------------------------------------------------------------------
def read(name): return list(csv.DictReader(open(name, encoding="utf-8")))
WAIT = [(float(r["clean"]), float(r["wait_min"])) for r in read("s21_wait_table.csv")]
POST = read("s21_posterior.csv")
TWIN = {r["twin"]: float(r["clean"]) for r in read("s21_twins.csv")}
REAL = [(int(r["remaining_glass"]), int(r["arrive_epoch"])) for r in read("s21_real_episodes.csv")]

# ---- 환경: 세정 시간 → 다음 세트 도착 간격 수 --------------------------------------------------------------
def wait_minutes(clean):          # 세정을 시작하기 전 줄 서서 기다리는 평균 시간(분): 표의 칸 사이를 직선으로 잇는다
    if clean <= WAIT[0][0]: return WAIT[0][1]
    if clean >= WAIT[-1][0]: return WAIT[-1][1]
    i = 0
    while clean > WAIT[i + 1][0]: i += 1
    f = (clean - WAIT[i][0]) / (WAIT[i + 1][0] - WAIT[i][0])
    return WAIT[i][1] * (1 - f) + WAIT[i + 1][1] * f
def arrival(clean, e1, e2):       # 줄 서서 기다림(두 지수분포의 평균) + 세정 + 반송, 30분 단위 올림
    return min(math.ceil((clean + wait_minutes(clean) * 0.5 * (e1 + e2) + TR) / EP), DMAX)
def draw_episode(rng):            # 한 판의 난수 재료: 남은 유리 · 단위 지수 둘 · 무작위화에서 세정 시간을 고르는 균등 난수
    return rng.int(R_HI - R_LO + 1) + R_LO, rng.exp(1.0), rng.exp(1.0), rng.u()
def sampler(weights=None, fixed=None):   # 환경 하나 = 균등 난수 → 세정 시간(고정 또는 사후분포에서 뽑기)
    if fixed is not None: return lambda uc: fixed
    cum, s, tot = [], 0.0, 0.0
    for w in weights: tot += w
    for w in weights: s += w / tot; cum.append(s)
    cum[-1] = 1.0
    cells = [float(r["clean"]) for r in POST]
    def pick(uc):
        i = 0
        while uc > cum[i]: i += 1
        return cells[i]
    return pick

def state(r, arrived, k, w): return r * NS + (KMAX + 1 + min(w, WMAX) if arrived else min(k, KMAX))
def step(r, k, arrived, w, a, D):  # 반환: 굶음 · 막힘 · 교체 손실, 끝났는가, 다음 상태
    idle = hold = sw = 0.0; done = False; nr, nk, na, nw = r, k, arrived, w
    if not arrived:
        if a == 1: sw = CSW * (2 + (1 if r > 0 else 0)); done = True          # 대기 중인 다른 세트로 지금 교체(나중에 다시 바꿈)
        else:
            idle = 0.0 if r > 0 else IDLE; nr = r - 1 if r > 0 else 0; nk = k + 1
            if nk >= D:
                na, nw = True, 0
                if nr == 0: sw = CSW; done = True                              # 도착 뒤 곧바로 교체
    else:
        if a == 1: sw = 2 * CSW; done = True
        else:
            hold = HOLD * (w + 1); nr = r - 1; nw = w + 1
            if nr == 0: sw = CSW; done = True
    return idle, hold, sw, done, nr, nk, na, nw

# ---- 표 형태 Q 학습 ----------------------------------------------------------------------------------------
def tabular_q(pick, episodes=EPISODES, alpha=ALPHA, eps=EPS, seed=1):
    rng = Rng(hash_seed("S21train", seed)); Q = [0.0] * (2 * NSTATE); N = [0] * (2 * NSTATE)
    for _ in range(episodes):
        r, e1, e2, uc = draw_episode(rng); D = arrival(pick(uc), e1, e2); k, arrived, w = 0, False, 0
        while True:
            s = state(r, arrived, k, w); u = rng.u()
            a = rng.int(2) if u < eps else (1 if Q[2 * s + 1] > Q[2 * s] else 0)   # 탐색(ε) 아니면 지금 가장 좋아 보이는 행동
            idle, hold, sw, done, nr, nk, na, nw = step(r, k, arrived, w, a, D)
            target = -(idle + hold + sw)
            if not done:
                s2 = state(nr, na, nk, nw); target += max(Q[2 * s2], Q[2 * s2 + 1])
            Q[2 * s + a] += alpha * (target - Q[2 * s + a]); N[2 * s + a] += 1
            if done: break
            r, k, arrived, w = nr, nk, na, nw
    return Q, N
def policy_table(Q, N, min_visits=MINV):   # 칸마다 0(기다림) · 1(지금 교체). 학습한 적이 적은 칸은 지금 규칙(기다림)으로 되돌림
    return [1 if N[2 * s] + N[2 * s + 1] >= min_visits and Q[2 * s + 1] > Q[2 * s] else 0 for s in range(NSTATE)]
def evaluate_policy(pol, episodes):         # episodes = [(남은 유리, 도착 간격 수)]. 판당 평균 Loss 와 항목
    tot = idle_t = hold_t = sw_t = 0.0
    for r, D in episodes:
        k, arrived, w = 0, False, 0
        while True:
            idle, hold, sw, done, r, k, arrived, w = step(r, k, arrived, w, pol[state(r, arrived, k, w)], D)
            idle_t += idle; hold_t += hold; sw_t += sw
            if done: break
    n = len(episodes); return (idle_t + hold_t + sw_t) / n, idle_t / n, hold_t / n, sw_t / n
def twin_episodes(pick, n=N_EVAL):          # 트윈 안 평가용 판 목록(고정 난수열)
    rng = Rng(hash_seed("S21eval")); out = []
    for _ in range(n):
        r, e1, e2, uc = draw_episode(rng); out.append((r, arrival(pick(uc), e1, e2)))
    return out
def randomized_training(weights, **kw):     # 도메인 무작위화: 판마다 세정 시간을 사후분포에서 뽑아 학습
    return tabular_q(sampler(weights=weights), **kw)

def intervals(ks):                          # [3,4,5,9] -> "3~5, 9"
    out, i = [], 0
    while i < len(ks):
        j = i
        while j + 1 < len(ks) and ks[j + 1] == ks[j] + 1: j += 1
        out.append(str(ks[i]) if i == j else "%d~%d" % (ks[i], ks[j])); i = j + 1
    return ", ".join(out) if out else "없음"
def quant(a, p):
    b = sorted(a); pos = (len(b) - 1) * p; lo = math.floor(pos); f = pos - lo
    return b[lo] + (b[lo + 1] - b[lo]) * f if lo + 1 < len(b) else b[lo]

if __name__ == "__main__":
    rule = [0] * NSTATE
    m_rule, i_rule, h_rule, s_rule = evaluate_policy(rule, REAL)
