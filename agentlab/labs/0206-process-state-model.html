기둥 4 · 실험실 6

공정을 상태와 전이로 적기

ESTC 모델과 사례 은행 — 마스크 한 장의 하루를 기록으로 읽고, 에이전트가 해도 되는 일을 표로 정하는 법

← 실험실 목록← 이전: 가성 인터락을 줄이는 spec다음: PPA를 벡터장으로 보기 →

마스크가 어디서 어디로 옮겨 다녔는지를 상태와 전이로 적어 두면, 글 기록으로는 답할 수 없던 물음에 답할 수 있고, 에이전트가 해도 되는 일을 표 한 장으로 정할 수 있습니다. 이 실험실의 가상 공장 60일에서 마스크·세트·챔버·블록이 상태를 바꾼 기록은 줄이고, 전부 허용된 전이이며 제약을 어긴 곳은 곳입니다. 같은 기록에서 판단이 들어간 사례 건(마스크 불량 → 리페어 건, 잡 체인지 대기 건)을 뽑았고, 불량으로 빠졌던 마스크가 다시 불량이 난 것은 건이었습니다. 이 값들은 가상 공장 한 벌의 것이며, 공장을 바꿔 뽑으면 달라지는 정도를 6절에서 직접 봅니다.

시작하기 전에

이미 아시는 것 — Loss 사유 코드(설비가 선 이유를 적는 이름표. 예: EQ-BD 고장, Q-MASK 마스크 정지), 마스크 세트·턴·잡 체인지(한 세트 4장이 한 블록에 걸려 한 턴을 돌고, 다음 세트로 바꾸는 일), 라벨과 놓친 이상의 역추적(0205), 판정 흐름(0104).

  • Loss 사유 코드
  • 마스크 세트·턴·잡 체인지
  • 라벨과 놓친 이상의 역추적
  • 판정 흐름

새로 이름을 붙이는 낱말은 여섯 개입니다. 쓰이는 자리에서 하나씩 정의하고, 정의한 뜻 그대로만 씁니다. 위 여섯과 함께 쓰는 부속 낱말(ESTC 모델·사례 기록·사례 은행)도 쓰는 자리에서 한 줄로 풉니다.

  • 개체 (entity)
  • 상태 (state)
  • 전이 (transition)
  • 가드 (guard)
  • 제약 (constraint)
  • 전이 궤적 (transition trajectory)

이 실험실에서 가져가는 것

  1. 실무에서 쓰는 곳 — 마스크 순환, 세정기 자리, 잡 체인지 대기. 담당 공정에서 ‘왜 섰나’를 물을 때 사건 한 줄이 아니라 그 마스크와 그 챔버가 거쳐 온 길로 답하는 데 씁니다.
  2. 손으로 연습 — 하루치 상태 막대를 읽고(3절), 마스크에 전이를 직접 요청해 가드에 걸려 보고(4절), 기록을 일부러 망가뜨려 검사가 잡아내는지 봅니다(5절).
  3. 다음 날 산출물 — 전이 표와 검사 함수, 사례 기록 양식과 검증 함수(9절 Python, 10절 양식).
  4. 기록할 데이터 — 마스크마다 상태가 바뀐 시각, 챔버 정지의 시작과 끝, 잡 체인지 대기와 막힘 사유, 판단한 사람과 근거, 결과를 다시 확인한 시각과 값(10절). 이 기록이 쌓여야 회사만 가진 데이터가 됩니다.
  5. 사람·규칙·에이전트의 몫 — 되돌릴 수 없는 전이는 사람이 승인하고, 가드와 제약 판정은 규칙이 하고, 궤적 질의와 사례 초안과 요약은 에이전트가 맡습니다(7절).
  6. 성과 환산 — 사례를 적는 시간과 같은 원인이 다시 났을 때 줄어드는 재조사 시간을 견줍니다(8절).
[문제] 0205까지 도구는 늘었습니다. 검정, 관리도, spec 재현은 모두 숫자 열을 받아 판정합니다. 이번 물음은 숫자 열이 아니라 일어난 순서가 답을 쥐고 있습니다.
가상 공장 60일 가운데 블록의 가 에 분 서고, 이어서 분을 더 섰습니다. 합쳐 분(약 시간)입니다.
(1) 왜 이렇게 오래 섰습니까? (2) 다시 그러지 않게 하려면 무엇을 바꿔야 합니까? (3) 그 판단을 에이전트가 맡아도 되는 범위는 어디까지입니까?

그날 담당자가 남긴 글 기록은 아래가 전부입니다. 같은 사건을 3절에서 상태 막대로 다시 봅니다.






여기서부터 위 사건을 이용한 풀이입니다




1왜 지금까지의 함수로는 이 물음에 답할 수 없나


위 글 기록에서 읽히는 것은 ‘마스크 불량으로 정지, 리페어 보냄’과 ‘장착할 마스크가 없어 다시 정지’, ‘리페어 끝’입니다. 사건은 적혔지만 두 가지는 어디에도 없습니다.


    
  
  • 그 마스크가 앞선 세정을 마치고 세트의 나머지 마스크를 몇 분 기다렸는가 — 아무 일도 일어나지 않은 시간이라 글로 남지 않습니다.
    • 
  
  • 그 마스크가 전에도 불량이었는가 — 사건 한 줄에는 그 마스크가 거쳐 온 길이 없습니다.
    • 



0101~0205의 함수에 이 물음을 그대로 던지면 어느 함수를 어떤 자료로 부를지, 그 결론으로 무엇을 해도 되는지를 정할 바탕이 없습니다. 필요한 것은 판정 함수가 아니라 무슨 일이 어떤 순서로 일어났는가를 같은 형식으로 적어 둔 바탕입니다. 이 두 물음의 답은 7절에서 그 바탕으로 채웁니다. 그 바탕의 이름과 만드는 법이 다음 절입니다.



  
MES 이력은 대개 사건의 목록입니다. ‘몇 시에 이 마스크가 세정기에 들어갔다’ 같은 줄은 있어도, 세정을 마친 마스크가 세트의 나머지를 기다린 시간이나 세정 대기열에서 줄을 선 시간처럼 아무 일도 일어나지 않은 시간은 기록이 없는 경우가 많습니다. 상태 기록은 ‘지금 어느 상태인가’를 시각마다 이어 붙이므로 그 시간이 저절로 보입니다.

  
MES 이력을 버리자는 뜻이 아닙니다. 이력의 한 줄을 상태 전이 한 줄로 바꿔 적고, 빠진 구간이 어디인지를 5절의 검사로 찾아내는 것이 출발점입니다.






2공정을 개체·상태·전이·제약으로 적는다


이 절의 네 가지, 곧 개체(Entity)·상태(State)·전이(Transition)·제약(Constraint)의 머리글자를 따 공정을 적는 이 방식을 ESTC 모델이라 부릅니다. 하나씩 차례로 정의합니다.


개체와 상태


먼저 ‘무엇의 상태를 적는가’를 정합니다. 상태를 가지는 대상, 곧 마스크·세트·챔버·블록·세정기·stocker·카세트·유리를 개체 (entity)라 부릅니다. 한 개체가 한 시각에 있는 단 하나의 자리를 상태 (state)라 부릅니다. 예를 들어 마스크의 상태는 ‘세정 중’이거나 ‘장착·증착 중’이고, 둘이 동시일 수는 없습니다.



  
표 1 · 이 공정의 개체 여덟 종류

  

  
세정기·stocker·카세트는 상태보다 수량이 중요해서 사용 중인 장수·적재율·여유 수로 적고, 유리는 수가 너무 많아 전이를 쌓지 않고 번호로 마스크의 기록에 잇습니다. 챔버의 정지 네 상태는 Loss 사유 코드(EQ-BD·Q-EVAP·EQ-PM·Q-MASK)와 같은 자리입니다.




전이와 가드


한 개체가 상태에서 상태로 옮겨 가는 일 한 번을, 시각과 원인(trigger)을 붙여 한 줄로 적은 것을 전이 (transition)라 부릅니다. 모든 전이가 아무 때나 일어나서는 안 됩니다. 전이가 일어나도 되는지 그 순간 확인하는 조건을 가드 (guard)라 부릅니다. 예를 들어 마스크가 ‘세정 대기열’에서 ‘세정 중’으로 가려면 세정기에 빈자리가 있어야 합니다.


아래 그림은 가상 공장 60일의 마스크 전이를 그대로 센 것입니다. 상자 안은 그 상태에 한 번 들어갔을 때 머문 평균 분이고, 화살표의 숫자는 그 전이가 일어난 횟수입니다.



  상태에 머문 평균 시간
  평균 체류 분=머문 분의 합옮겨 간 횟수
  그 상태에서 다음 상태로 옮겨 가기까지 머문 분을 모두 더하고, 옮겨 간 횟수로 나눕니다. 기록의 마지막에 아직 머물고 있는 상태는 횟수에 넣지 않습니다.




  
그림 1 · 마스크 한 장의 상태와 전이 (60일 합계)

  
  
장착·증착 중세정 경로(반송·대기·세정·짝 대기·보관 반송)리페어리페어를 거친 길

  

  
그림에 없는 길이 표 끝에 있습니다. 턴 도중 리페어에서 돌아와 장착하지 못한 마스크도 세트와 함께 세정으로 보내져 ‘대기 → 세정기로 반송’이 일어납니다.




제약


가드가 한 순간의 조건이라면, 모든 시각에 지켜져야 하는 개체 사이의 규칙을 제약 (constraint)이라 부릅니다. 세정 중인 마스크는 동시에 27장을 넘을 수 없다는 규칙이 그 예입니다. 5절에서 이 규칙을 기록 전체에 대고 검사합니다.



  
표 2 · 제약 여섯 개

  





  
판단이 달라지는 지점마다 하나입니다. 마스크 ‘짝 대기’는 세정은 끝났지만 보관으로 갈 수 없는 상태라서 ‘세정 중’과 따로 두었고, ‘세정 대기열’은 세정기에 자리가 나야 풀리는 상태라서 ‘세정기로 반송’과 따로 두었습니다.

  
반대로 반송 중인 마스크가 어느 복도를 지나는지처럼 판단을 바꾸지 않는 구분은 나누지 않습니다. 잘게 나눌수록 기록해야 할 시각이 늘고 현장이 적지 않게 됩니다. 처음에는 거칠게 나누고, 사건을 설명하는 데 모자란 곳에서만 쪼갭니다.






3연습 1 — 하루치 전이 궤적 읽기


한 개체의 전이 기록을 시각 순으로 이은 것을 전이 궤적 (transition trajectory)이라 부릅니다. 이 가상 공장의 한 블록과 하루를 골라 챔버 4개, 세트 3개, 블록, 세정기 사용 중 장수를 같은 시간축에 놓고, 마스크 한 장의 궤적을 따라가 보겠습니다.



  
블록·날짜·마스크 선택 — 같은 시간축의 상태 막대

  
이렇게 해 보세요. 처음 화면은 위 [문제]의 사건이 일어난 블록과 날입니다. 챔버 줄에서 마젠타 막대(마스크 정지)를 찾고, 그 아래 마스크 줄에서 같은 시각에 그 마스크가 장착 → 리페어로 옮겨 간 곳을 확인하십시오. 이어서 날짜를 하루씩 넘기며 정지가 없는 날과 비교해 보십시오.

4연습 2 — 전이를 요청하고 가드에 걸려 보기


에이전트가 공정에 일을 시킨다면 가장 안전한 방식은 ‘마스크 하나를 이 상태로 옮겨 달라’고 요청하게 하고, 그 요청을 세 단계로 걸러 내는 것입니다. 1) 표에 있는 전이인가, 2) 사람의 승인이 필요한 전이인가, 3) 그 순간 가드를 통과하는가입니다. 통과한 요청만 실행됩니다.



  
시각·마스크·옮겨 갈 상태 — 요청 결과

  
이렇게 해 보세요. 아래 단추 가운데 [세정기가 가득 찬 때]를 누르십시오. 세정 대기열의 마스크가 ‘세정 중’으로 가려는 요청이 가드에서 거절되고, 이유에 그 순간의 실제 장수가 나옵니다. 시각 슬라이더를 움직이면 세정기 사용 수와 요청 결과가 함께 바뀝니다. 세정기 한도 27장은 설비가 정하는 값이라 슬라이더로 두지 않았습니다.

5제약 검사 — 기록의 구멍을 잡는다


60일 기록 전체에 대고 표와 제약을 확인해 봅니다. 확인하는 것은 다섯 가지입니다. 표에 없는 전이는 없는가, 한 개체의 직전 상태와 다음 줄의 출발 상태가 이어지는가, 세정 중인 마스크가 한도를 넘지 않는가, 한 블록에 증착 중인 세트가 둘이 아닌가, 챔버가 상태마다 머문 시간의 합이 기록 기간과 같은가입니다.



  
기록 전체 검사 — 일부러 망가뜨려 잡히는지 확인

  
이렇게 해 보세요. 처음에는 위반이 0입니다. [전이 한 줄 지우기]를 누르면 줄 수가 하나 줄고 이음새 규칙 C3이 한 곳에서 걸립니다. [순서 뒤집기]는 연속한 두 전이의 내용을 맞바꿉니다. [세정 한 장 더]는 세정기가 가득 찬 순간에 대기 중인 마스크 하나를 끼워 넣어 C1이 걸리게 합니다. 하나를 누른 뒤 [원래대로]를 눌러 0으로 돌아오는지도 확인하십시오.

  

    
    
    
    
  

  

  

  




사람이 엑셀로 이어 붙인 기록에서는 이런 구멍이 의외로 쉽게 생깁니다. 줄 하나를 빠뜨려도, 정렬을 잘못해도, 같은 마스크를 두 자리에 적어도 눈으로는 보이지 않습니다. 상태 기록은 ‘이어지는가’를 기계가 매번 확인할 수 있어서, 구멍이 기록 단계에서 드러납니다.




6사례 은행 — 궤적 한 토막과 판단과 결과


궤적은 ‘무슨 일이 있었나’를 알려 주지만 ‘무엇을 판단했고 어떻게 됐나’는 알려 주지 않습니다. 판단이 들어간 순간만 따로 모아 궤적의 한 토막, 판단, 결과를 한 건으로 적은 것이 사례 기록이고, 그 모음이 사례 은행입니다. [문제]의 사건을 사례 기록 한 건으로 적으면 아래와 같고, 오른쪽이 같은 사건의 글 기록입니다.



  
사례 기록 (JSON)

  
같은 사건의 글 기록

    
글 기록에는 ‘판단 근거의 숫자’, ‘결과를 확인한 시각과 값’, ‘다른 기록과 잇는 번호’가 없습니다. 오른쪽 사건에 JSON의 links 칸이 이어 주는 것은 이벤트 번호와 턴 번호이고, 이 번호로 PPA·FDC 기록을 붙일 수 있습니다.

REQUIRED = ["case_id", "t_detect", "entity", "id", "state_before", "evidence", "decision",
            "action", "state_after", "outcome", "label", "links"]


def check_trajectory(df, end=None, cap=CAP):
    """전이 기록을 처음부터 다시 훑어 위반 목록 [(규칙, 시각, 개체, 내용)] 을 돌려준다.
    T0 표에 없는 전이 · C3 직전 상태와 from 불일치 · C1 세정 동시 수 > cap · C2 블록당 증착 세트 > 1 · C4 챔버 체류 합 ≠ end.
    쓰면 안 되는 때: 전이를 시각 순으로 정렬해 두지 않았을 때(같은 시각이면 기록한 순서를 지켜야 함)."""
    out, last, cleaning, dep, ch = [], {}, 0, {}, {}
    for r in df.itertuples(index=False):
        key = (r.entity, r.id)
        if (r.entity, r.from_, r.to) not in TRANSITIONS:
            out.append(("T0", r.t, r.id, f"표에 없는 전이 {r.from_}→{r.to}"))
        prev = last.get(key, "init")
        if r.from_ != prev:
            out.append(("C3", r.t, r.id, f"직전 상태 {prev} 인데 from={r.from_}"))
        last[key] = r.to
        if r.entity == "mask":
            cleaning += (r.to == "cleaning") - (r.from_ == "cleaning")
            if cleaning > cap:
                out.append(("C1", r.t, r.id, f"세정 중 {cleaning}장 > 한도 {cap}"))
        elif r.entity == "set":
            b = r.id[:3]
            dep[b] = dep.get(b, 0) + (r.to == "dep") - (r.from_ == "dep")
            if dep[b] > 1:
                out.append(("C2", r.t, r.id, f"블록 {b} 에 증착 중 세트 {dep[b]}개"))
        elif r.entity == "chamber":
            ch.setdefault(r.id, []).append(r.t)
    if end is not None:
        for cid, ts in ch.items():
            if ts[0] != 0 or sum(b - a for a, b in zip(ts, ts[1:])) + (end - ts[-1]) != end:
                out.append(("C4", end, cid, "상태별 체류 분의 합이 기록 기간과 다름"))
    return out


def dwell(df, ident, end):
    """한 개체가 상태마다 머문 분. 마지막 상태는 end 까지 센다.
    쓰면 안 되는 때: 기록 시작 전에 이미 있던 상태의 앞부분은 알 수 없으므로 그 구간은 빠진다."""
    rows = df[df.id == ident]
    out = {}
    for a, b in zip(rows.itertuples(), list(rows.itertuples())[1:] + [None]):
        out[a.to] = out.get(a.to, 0) + ((b.t if b is not None else end) - a.t)
    return out


def snapshot(df, t):
    """시각 t 까지의 상태표와 자원 수. request_transition 의 입력."""
    part = df[df.t <= t]
    state = {(r.entity, r.id): r.to for r in part.drop_duplicates(["entity", "id"], keep="last").itertuples()}
    cleaning = sum(1 for (e, i), s in state.items() if e == "mask" and s == "cleaning")
    return state, {"cleaning": cleaning}


def request_transition(state_now, entity, ident, to, resources):
    """에이전트가 도구를 부르기 전의 문지기: 표에 있는가 → 사람 승인이 필요한가 → 가드를 통과하는가. (허용 여부, 이유).
    쓰면 안 되는 때: 가드의 값(세정기 사용 수)이 오래된 것이면 허용을 믿으면 안 된다 — 요청 직전에 다시 읽는다."""
    now = state_now.get((entity, ident), "init")
    key = (entity, now, to)
    if key not in TRANSITIONS:
        return False, f"표에 {now} → {to} 전이가 없습니다"
    guard, human = TRANSITIONS[key]
    if human:
        return False, "되돌릴 수 없는 전이라 사람의 승인이 필요합니다"
    if guard == "cleaner_free" and resources["cleaning"] >= CAP:
        return False, f"세정기 {resources['cleaning']}/{CAP}장이 사용 중이라 자리가 없습니다"
    if guard == "set_ready":
        block, sset = ident[:3], ident[4]
        if state_now.get(("set", f"{block}-{sset}")) != "ready":
            return False, "세트가 ready 가 아닙니다"
        if any(state_now.get(("set", f"{block}-{x}")) == "dep" for x in "ABC"):
            return False, "같은 블록에 증착 중인 세트가 이미 있습니다"
    return True, "표에 있고 가드를 통과했습니다"


def validate_case(rec):
    """사례 기록 한 건의 오류 목록(빈 목록이면 통과). 필수 칸 · 시각 순서 · 전이가 표에 있는가 · 사람 승인 칸.
    쓰면 안 되는 때: 결과(outcome)를 아직 모르는 사례를 저장하려고 이 함수를 끄지 않는다 — 결과 칸은 '미확인' 으로 채워 둔다."""
    errs = [f"필수 칸 없음: {k}" for k in REQUIRED if k not in rec]
    if errs:
        return errs
    if rec["outcome"]["t_check"] < rec["t_detect"]:
        errs.append("결과 확인 시각이 감지 시각보다 앞")
    a = rec["action"]["transition"]
    key = (rec["entity"], a["from"], a["to"])
    if key not in TRANSITIONS and a["from"] != "wait_jc":
        errs.append(f"행동 전이 {a['from']}→{a['to']} 가 표에 없음")
    elif key in TRANSITIONS and TRANSITIONS[key][1] and rec["action"].get("approved_by") in (None, "", "rule"):
        errs.append("사람 승인이 필요한 전이인데 승인자 칸이 비어 있음")
    return errs


def append_case(path, rec):
    """검사를 통과한 사례만 JSON Lines 로 한 줄 덧붙인다. 통과하지 못하면 쓰지 않고 오류 목록을 돌려준다.
    쓰면 안 되는 때: 회사 사례 파일은 회사 안에만 둔다 — 공개 저장소·외부 서비스에 올리지 않는다."""
    errs = validate_case(rec)
    if not errs:
        with open(path, "a", encoding="utf-8") as f:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")
    return errs
