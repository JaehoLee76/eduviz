에이전트 평가

사람 결론과 맞대어 일치율과 구간을 재고, 계획 모델의 예측을 실제 전이와 견주어 — 얼마나 믿을 수 있는지를 숫자로

← 실험실 목록← 이전: 에이전트 구조 시제품다음: Loss 분류 체계와 파레토 →

에이전트를 라인에 쓰기 전에, 그리고 쓰는 동안, ‘얼마나 믿을 수 있나’를 숫자로 말해야 합니다. ‘14일 돌려 보니 괜찮더라’는 근거가 되지 않습니다. 이 실험실은 두 숫자로 답합니다. 하나는 같은 날 같은 자료에서 사람이 내린 결론과 에이전트의 결정이 얼마나 일치하는가(판단의 질)이고, 다른 하나는 에이전트가 계획에 쓰는 단순한 모델의 예측이 실제 상태 전이와 얼마나 어긋나는가(계획의 질)입니다. 둘 다 실행 기록이 쌓여야만 잴 수 있습니다. 무대는 0401 과 같은 가상 공장 일(대표 시드 , 챔버 개)입니다. 이 공장에서는 어느 날 어떤 고장이 들었고 어느 챔버의 마스크가 언제 바뀌었는지를 우리가 알고 있으므로, 그 정답이 사람 결론을 대신합니다. 현장에는 이 정답이 없고 사람도 틀립니다(2절).

시작하기 전에

이미 아시는 것 — 0401 의 에이전트·정책·실행 기록·승인 대기열, 0400 의 점검과 주입 고장, 0202 의 놓침과 헛알람의 맞바꿈, 0206 의 전이 기록(simulateLoss trace)과 체류 시간, 0205 의 시간순 분할, 0101 의 신뢰구간.

  • 에이전트·정책·실행 기록 (0401)
  • 점검 · 주입 고장 (0400)
  • 놓침 · 헛알람 (0202)
  • 전이 기록 · 체류 시간 (0206)
  • 시간순 분할 (0205)
  • 신뢰구간 (0101)

새로 이름을 붙이는 낱말은 여섯 개입니다. 쓰이는 자리에서 하나씩 정의하고, 정의한 뜻 그대로만 씁니다.

  • 사람 결론 (human label)
  • 평가 단위 (evaluation unit)
  • 일치율 (agreement rate)
  • 윌슨 구간 (Wilson interval)
  • 계획 모델 (planning model)
  • sim-real gap

이 실험실에서 가져가는 것

  1. 실무에서 쓰는 곳 — 에이전트를 라인에 시범 적용할지, 확대할지, 멈출지를 정하는 근거(2~7절).
  2. 손으로 연습 — 에이전트의 결정과 사람 결론을 맞대어 혼동표·일치율·구간을 내 보고, 날 수와 시드 수를 늘리면 구간이 좁아지는 것을 보고, 계획 모델의 예측과 실제 전이의 차이를 재 봅니다(2~6절).
  3. 다음 날 산출물 — agreement_table·wilson_ci·sim_real_gap Python 함수(9절)와 에이전트 평가 보고서 양식(10절).
  4. 기록할 데이터 — 에이전트 결정과 사람 결론을 같은 (날, 챔버) 칸에, 결론을 낸 사람과 시각, 계획 예측값과 실제값(10절).
  5. 사람·규칙·에이전트의 몫 — 시범 승인과 중단 기준·사람 결론 쓰기는 사람, 평가 단위·혼동표·구간 계산은 규칙, 실행 기록과 예측 남기기는 에이전트(7절).
  6. 성과 환산 — 놓침과 헛요청의 비용을 가정해 에이전트와 사람만 할 때의 기대 비용을 견줍니다(8절).
[문제] 0401 에이전트를 실제 라인에 시범 적용할지 정해야 합니다. (1) ‘가상 공장 일을 돌려 보니 괜찮았다’는 근거가 됩니까. 근거를 숫자로 내십시오. (2) 에이전트가 계획에 쓰는 단순 모델은 실제 상태 전이와 얼마나 어긋납니까.

1절에서 막히는 곳을 확인하고, 2~6절에서 재는 법을 만들고, 7절에서 이 두 물음으로 돌아옵니다. 비용·사람의 오류율은 현장 값으로 바꿔야 할 가정입니다(8절).

여기서부터 가상 공장의 정답과 맞댄 평가입니다

1첫 시도 — 14일 기록을 훑으면 그럴듯합니다

0401 에이전트가 대표 시드의 일을 돈 기록입니다. 점검 허용 수가 다른 정책 셋 가운데 하나를 골라 훑어 보십시오. 어느 정책이든 기록은 말이 됩니다 — 점검에 걸린 날은 멈추고, 분석한 날에는 이유가 붙은 요청이 나갑니다.

14일 실행 기록 — 정책을 골라 훑어 보기

막힘. 기록이 그럴듯한 것과 믿을 수 있는 것은 다릅니다. 세 가지가 정해져 있지 않습니다.

  1. 무엇과 견주는가. ‘괜찮다’는 말에는 견줄 기준이 없습니다. 같은 날 같은 자료를 사람이 보았다면 어떤 결론을 냈을지가 있어야 합니다.
  2. 어느 칸을 세는가. 날을 세는지, 챔버를 세는지, 요청을 세는지에 따라 ‘맞았다’의 뜻이 달라집니다.
  3. 14일은 많은가. 이 14일에 마스크 교체가 든 챔버는 개뿐이고, 그것을 알아챘는지 가릴 수 있는 칸은 그만큼뿐입니다.

그래서 먼저 기준(사람 결론)과 셈의 단위(평가 단위)를 정합니다.

2이름 — 사람 결론 · 평가 단위 · 일치율

  • 사람 결론 (human label) — 같은 날 같은 자료를 사람이 보고 내린 판정(조치가 필요한지·원인이 무엇인지)입니다. 평가의 기준선입니다. 이 가상 공장에서는 주입한 고장과 마스크 교체라는 정답이 사람 결론을 대신합니다. 현장에서는 사람도 틀립니다.
  • 평가 단위 (evaluation unit) — 맞았는지 셀 한 칸입니다. 여기서는 날 판정(날 하나), 변경점((날, 챔버) 하나), 요청((날, 챔버) 하나와 전체에 대한 spec 칸 하나) 셋입니다. 단위를 정하지 않으면 일치율이 무엇의 비율인지 알 수 없습니다.
  • 일치율 (agreement rate) — 평가 단위 가운데 에이전트의 결정과 사람 결론이 같은 칸의 비율입니다. 대부분의 칸이 ‘없음’이면 높게 나오기 쉬우므로, 놓침과 헛요청을 나눈 혼동표와 함께 씁니다.

셋의 사람 결론 규칙은 다음과 같습니다. 정답은 모두 이 공장이 만든 사실입니다.

평가 단위칸 하나사람 결론(정답)에이전트 결정이 14일의 칸 수
날 판정날 하나그날 적재된 표에 고장이 들었으면 ‘멈춰야 하는 날’, 아니면 ‘분석해도 되는 날’점검에서 멈췄으면 ‘멈춤’, 분석했으면 ‘분석’
변경점(날, 챔버) 하나그 챔버에 마스크 교체가 있었고, 고장 없는 자료로 잰 교체 전후 보정 후 Mx 평균 차의 크기가 ppm 이상이면 교체가 든 날의 칸이 ‘변경 있음’. 그 밖의 칸은 ‘없음’그 챔버를 새 변경점으로 올렸으면 ‘있음’. 올린 날이 교체일부터 허용 지연 안이면 일치
요청(날, 챔버) 하나, 그리고 전체(spec) 하나마스크 교체마다(크기와 무관) 교체가 든 날의 칸이 ‘기준 측정 필요’. 리페어·마스크 제외·보정값 입력·spec 변경은 이 공장에 그럴 사정을 심지 않았으므로 어느 칸이든 ‘불필요’기준 측정 요청이 교체일부터 허용 지연 안에 나가면 일치. 나머지 요청은 모두 헛요청

셈의 세부 규칙입니다. 1) 허용 지연 — 에이전트는 마스크 이력을 점검을 통과한 날에만 읽으므로 교체를 며칠 뒤에 알아챌 수 있습니다. 교체일부터 허용 지연(일) 안에 나간 신호만 ‘일치’로 셉니다. 2) 허용 지연을 넘겨 늦게 나간 신호는 놓침 한 칸으로만 세고, 그 신호가 나간 날을 헛으로 또 세지 않습니다. 3) 판정 기한(교체일 + 허용 지연)이 14일을 넘는 교체는 아직 판정할 수 없어 칸에서 뺍니다. 4) 날 판정은 고장이 든 날 모두를 ‘멈춰야 하는 날’로 둡니다. 고장이 들었어도 결과는 정답과 같았던 날이 있었지만(0400), 그것을 알아보려면 정답본이 필요하므로 에이전트가 쓸 수 있는 기준이 아닙니다.

먼저 짚어 둘 것. 이 정답은 가상 공장이 알려 주는 것이고, 현장에는 없습니다. 현장에서는 담당자가 같은 날 같은 자료를 보고 결론을 쓰는데, 그 사람도 틀리고 사람마다 다릅니다. 그래서 현장 평가에서는 사람 결론을 낸 사람과 시각을 함께 적고, 사람끼리의 일치율도 따로 잽니다(10절). 아래 숫자는 ‘정답이 있는 세계에서의 평가’이며, 현장에서는 이만큼 후하게 나오지 않습니다.
대표 시드 14일의 혼동표 셋
무엇을 볼지 먼저. 1) 정책을 바꿔 가며 ‘변경점’ 표의 일치율과 아래쪽 ‘늘 없음이라고만 답하면’ 숫자를 견주십시오. 2) 허용 지연을 0 에서 5 로 올려 보십시오. 늦게 나간 신호가 놓침에서 일치로 옮겨 가는 것을 볼 수 있습니다.

충분한지는 일치율만으로 알 수 없습니다. 칸의 대부분이 ‘없음’이면 아무것도 하지 않고 늘 ‘없음’이라고만 답해도 일치율이 높게 나옵니다. 그래서 위 표에는 ‘늘 없음이라고만 답하면’ 숫자를 나란히 두었습니다. 에이전트의 일치율이 그 숫자와 같거나 낮으면, 일치율은 에이전트가 쓸모 있다는 증거가 못 됩니다.

그다음에 볼 것은 놓침과 헛요청의 건수입니다. 놓침은 마스크 교체를 기준 측정 없이 넘기는 일이고, 헛요청은 사람이 쓸데없이 승인·반려를 처리하게 만드는 일입니다. 둘의 비용이 다르므로 일치율 하나로 합쳐 말하지 않고 따로 적습니다(8절). 3절에서 이 숫자가 얼마나 흔들리는지(윌슨 구간)를 봅니다.

틀릴 수 있다고 보고, 사람 결론 자체도 재 둡니다. 같은 날 같은 자료를 두 사람에게 따로 보여 주고 두 사람의 일치율을 잽니다. 사람끼리 일치율이 80% 라면 에이전트가 사람 결론과 90% 일치한다는 말은 ‘사람보다 낫다’도 ‘맞다’도 뜻하지 못합니다. 에이전트와 사람의 일치율이 사람끼리의 일치율에 가까우면 그것이 이 평가가 줄 수 있는 가장 좋은 결과입니다.

그래서 사람 결론을 쓸 때 결론을 낸 사람·시각·근거 자료를 같은 칸에 적고, 에이전트가 만든 자료를 사람 결론으로 쓰지 않습니다. 같은 실수를 공유하기 때문입니다(10절).

3윌슨 구간 — 14일로 어디까지 말할 수 있나

  • 윌슨 구간 (Wilson interval) — 비율(여기서는 일치율)의 신뢰구간입니다. 평가 단위가 적을 때, 또 비율이 0 이나 1 에 가까울 때 ‘비율 ± 2 표준오차’(0101 의 방식을 비율에 그대로 쓴 것)보다 덜 틀립니다.

일치한 칸이 k 개, 전체 칸이 n 개이면 일치율은 p̂ = k/n 이고, 신뢰도 95% 에서 z = 입니다(표준정규분포의 값).

윌슨 구간 — 일치율 p̂ 의 95% 구간 p^+z22n 1+z2n ± z 1+z2n p^(1−p^)n + z24n2 앞 덩어리가 구간의 가운데, 뒤 덩어리가 반쪽 폭입니다. 단순 구간은 p̂ ± z·√(p̂(1−p̂)/n) 로, p̂ 가 1 이면 폭이 0 이 되어 ‘틀릴 수 없다’는 말이 됩니다.
같은 정책의 일치율 — 대표 시드의 14일 vs 시드를 모은 것
무엇을 볼지 먼저. 1) ‘날 수’를 14 에서 1 로 줄이면 대표 시드의 구간이 얼마나 넓어지는지, 2) ‘시드 수’를 1 에서 늘리면 모은 구간이 좁아지는 것을 보십시오. 14일 한 번의 구간이 모은 구간보다 훨씬 넓습니다. 시드 200개의 계산은 이 화면이 열린 뒤 조금씩 진행됩니다.

4정책별 평가 — 일치율은 비슷한데 놓침과 헛요청이 다릅니다

0401 에서 점검 허용 수를 바꾸면 에이전트의 행동이 달라졌습니다. 그 맞바꿈을 이제 숫자로 봅니다. 아래 그림은 단위마다 정책 셋의 일치율과 윌슨 구간이고, 세로 눈금은 ‘늘 없음이라고만 답하면’ 나오는 일치율입니다. 시드 수와 허용 지연은 2·3절의 슬라이더와 같은 값이고, 여기서도 옮길 수 있습니다.

정책 셋 × 평가 단위 셋 — 일치율과 놓침·헛요청

5이름 — 계획 모델과 sim-real gap

  • 계획 모델 (planning model) — 에이전트가 ‘마스크가 언제 돌아오나, 대기가 얼마나 되나’를 미리 셀 때 쓰는 단순 모델입니다(평균 시간·고정 순서).
  • sim-real gap — 계획 모델의 예측과 실제 상태 전이 기록의 차이입니다. 평균 차(치우침)와 흩어짐, 차가 큰 상황을 함께 봅니다. 이 실험실에서는 예측 시각 − 실제 시각(분)이고, 음수이면 실제가 예측보다 늦었다는 뜻입니다.

‘실제’는 0206 의 상태 전이 기록(simulateLoss 의 trace, 가상 공장 일)입니다. 마스크 한 장이 증착을 마치고 in_use 를 떠난 시각에서 다시 stock 에 들어오는 시각까지가 한 경로이고, 경로마다 실제 입고 시각이 기록에 있습니다. 계획 모델은 같은 시뮬레이터 설정의 평균값만 씁니다.

계획 모델 판 1 — 평균값만 더함 (세정 대기·짝 대기·고장은 무시) 정상 경로t예측=t떠남+TR+CLEAN+TOSTK 리페어 경로t예측=t떠남+TR+REPAIR_MED+CLEAN TR = 분(세정기로 반송), CLEAN = 분(세정), TOSTK = 분(stocker 로 반송), REPAIR_MED = 분(리페어 중앙값). 정상 경로 예측은 분, 리페어 경로 예측은 분입니다.

판 2는 거기에 세정기 대기열을 넣은 것입니다. 마스크가 떠나는 순간의 세정기 상태(세정 중인 마스크와 끝날 시각, 줄 선 마스크, 오는 중인 마스크)를 보고, 세정기 대가 먼저 온 순서대로 비는 대로 마스크를 받는다고 계산해 이 마스크가 세정을 시작할 시각을 구합니다. 앞으로 새로 떠날 마스크는 모르므로, 그것까지는 반영하지 못합니다.

마스크 한 장의 실제 경로와 두 판의 예측
무엇을 볼지 먼저. 1) ‘중앙 경로’에서 판 1 과 판 2 의 세로선이 실제 도착(오른쪽 끝)에서 얼마나 떨어져 있는지, 2) ‘세정 대기가 긴 경로’에서 판 1 은 크게 빗나가는데 판 2 는 얼마나 따라가는지, 3) ‘리페어 경로’에서는 두 판이 같고 둘 다 빗나가는 것을 보십시오.

경로 하나가 아니라 전체 경로의 gap 분포를 봅니다(대표 설정 일). 아래 그림은 정상 경로의 gap 이고, 리페어 경로는 흩어짐이 너무 커서 표로 따로 둡니다.

gap 분포 · 구성 · 큰 gap 의 공통점

sim-real gap 만큼 덜 믿습니다. 시뮬레이터 안에서 잰 일치율은 시뮬레이터가 에이전트에게 준 자료와 정답 위의 숫자입니다. 현장은 시뮬레이터에 없는 일(자료 고장의 종류, 사람이 다르게 부르는 사유, 설비의 예외)이 섞이므로 같은 숫자가 나오지 않습니다. 계획 모델의 gap 은 그 ‘시뮬레이터와 현실의 거리’를 하나의 숫자로 재는 연습이고, 6절은 그 거리가 어디에서 큰지 기록으로 가리킬 수 있음을 보였습니다.

그래서 현장에서는 시범 기간의 실행 기록과 사람 결론으로 이 평가를 다시 돌립니다. 시뮬레이터 평가는 라인에 쓰기 전에 ‘이 정도면 시범을 해 볼 만한가’를 거르는 용도입니다(7절).

7착지 — 평가 보고서 한 장과 사람·규칙·에이전트

맨 앞의 두 물음으로 돌아갑니다. 아래 보고서는 화면의 정책과 허용 지연 값에서 나온 숫자로 채웠습니다.

누가맡는 일
사람시범 적용의 승인과 중단 기준 정하기 · 사람 결론 쓰기(결론을 낸 사람과 시각 기록) · 사람끼리 일치율 재기 · 평가 단위와 허용 지연의 정의 승인 · 승인 대기열 처리
규칙평가 단위·혼동표·일치율·윌슨 구간의 계산 방식 · 판정 기한 규칙 · 계획 모델의 식과 설정값 · 평가를 다시 돌리는 조건(정책·공정이 바뀔 때)
에이전트실행 기록과 계획 예측을 같은 키로 남기기 · 평가표 초안 만들기 · 놓침·헛요청 사례 목록 모으기 · 사람이 볼 항목 요약

단계 4 마무리 — 에이전트가 쓸 손발을 다섯 편으로 만들었습니다

단계 5(Loss)로 가는 다리. 지금까지는 에이전트가 하루 한 번 자료를 보고 조치를 요청하는 일을 평가했습니다. 단계 5 에서는 Loss(라인에서 잃는 시간과 장수)를 같은 틀로 다룹니다. Loss 사유를 분류하고 예측하는 모델도 사람 결론과 맞댄 혼동표·구간과, 시뮬레이터와 실제의 gap 으로 재는 것이 이 실험실의 방식 그대로 쓰입니다.

한 번으로 끝나지 않습니다. 정책이나 공정이 바뀔 때마다, 그리고 실행 기록이 쌓이는 대로 다시 돌립니다. 점검 허용 수나 변경점 문턱을 바꾸면 같은 자료에서도 행동이 바뀌므로 지난 평가는 그 정책에만 맞습니다. 공정이 바뀌어도(마스크 종류, 세정 시간, 센서 교정) 계획 모델의 gap 이 달라집니다.

0305 의 드리프트 감시와 같은 생각입니다. 모델의 오차가 서서히 커지는 것을 알아채려면 평가를 정기적으로 다시 하고, 지난 평가와 이번 평가의 구간을 나란히 둡니다. 평가 기간과 개발 기간을 섞지 않도록 시간순으로 나눕니다(0205).

8현장에서 환산하면

얻는 것은 에이전트가 사람보다 놓침이 적고 헛요청이 적을 때 줄어드는 비용이고, 치르는 것은 에이전트와 평가를 만들고 유지하는 시간입니다. 놓침 한 건(마스크 교체를 기준 측정 없이 넘김)·헛요청 한 건(쓸데없는 승인 처리)·고장 든 날을 분석해 버린 하루(틀린 표 위에서 결정을 내림)의 비용을 가정해, 시드를 모은 평균 건수와 곱합니다. 점검을 풀면 앞의 둘은 줄고 셋째는 늘어나므로 셋을 함께 넣습니다. 작으면 작다고 적습니다. 아래 다섯 값은 가정이니 현장 값으로 바꾸십시오.

에이전트 vs 사람만 — 14일당 기대 비용 (분)
무엇을 볼지 먼저. 1) 표의 세 에이전트 열에서 기대 비용이 가장 낮은 정책이 비용 가정을 바꾸면 달라지는지, 2) 사람이 놓치는 비율을 바꾸면 사람만 할 때와 에이전트의 순서가 어디서 뒤바뀌는지 보십시오.

사람만 할 때의 건수는 같은 14일 동안 사람이 같은 칸을 보고 낼 건수의 가정입니다. 이 숫자는 ‘사람은 틀리지 않는다’는 가정을 깨기 위한 칸이며, 실제 값은 사람끼리의 일치율과 사례 기록으로 채웁니다. 회사에서는 같은 식에 단가를 곱해 금액으로 적습니다.

아래 코드는 표준 라이브러리와 pandas 만 씁니다. 입력은 0401 에이전트 실행 기록의 요약(s15_agent_log_115.csv)과 사람 결론(s15_human_labels_115.csv), 0206 의 전이 기록(mask_transitions.csv) 셋이고, 코드와 같은 폴더에 두면 그대로 돌아갑니다. 에이전트 기록과 사람 결론을 따로 둔 것은 에이전트가 만든 자료를 사람 결론으로 쓰지 않기 위해서입니다. 구간은 wilson_ci 로 직접 계산합니다.

import math, os
from statistics import NormalDist
import pandas as pd

# ---- 가정·설정: 현장 값으로 바꿀 곳 ------------------------------------------------
DELTA_H = 0.5          # 사람이 '변경 있음'으로 보는 교체 전후 보정 후 Mx 차 문턱 (ppm)
GRACE = 2              # 허용 지연(일): 교체가 든 날부터 이만큼 안에 알아채야 '일치'
DAYS = 14              # 평가 기간(일)
CHAMBERS = [b + "-CH" + str(c) for b in ("B02", "B03") for c in (1, 2, 3, 4)]
POLICIES = [("strict", "엄격"), ("two", "2개 허용"), ("off", "점검 끔")]
UNITS = [("day", "날 판정"), ("change", "변경점"), ("request", "요청")]
PLAN = {"CAP": 27, "TR": 30, "CLEAN": 180, "TOSTK": 20, "REPAIR_MED": 600}   # 계획 모델의 평균값(분). 세정기 27대·반송 30·세정 180·입고 20·리페어 중앙값 600


# ---- 1. 평가 단위와 혼동표 ----------------------------------------------------------
def load_inputs(folder="."):
    log = pd.read_csv(os.path.join(folder, "s15_agent_log_115.csv"), keep_default_na=False)
    labels = pd.read_csv(os.path.join(folder, "s15_human_labels_115.csv"), keep_default_na=False)
    return log, labels


def _first(items, used, ch, lo, hi):
    """아직 안 쓴 기록 가운데 챔버가 같고 날이 [lo, hi] 안인 첫 번째의 번호. 없으면 -1."""
    for i, (d, c) in enumerate(items):
        if i not in used and c == ch and lo <= d <= hi:
            return i
    return -1


def _pending(items, used, ch, day):
    for i, (d, c) in enumerate(items):
        if c == ch and d >= day:
            used.add(i)


def agreement_table(log, labels, unit, policy, grace=GRACE, days=DAYS):
    """평가 단위 하나의 혼동표. 사람 결론(labels)과 에이전트 행동(log)을 같은 (날, 챔버) 칸에서 맞댄다.
    지연 허용: 교체가 든 날부터 grace 일 안에 알아채면 일치, 그 뒤면 놓침(그 신호는 헛으로 세지 않음). 판정 기한이 아직 안 지난 교체는 칸에서 뺀다."""
    L = log[log["policy"] == policy]
    c = {"tp": 0, "fn": 0, "fp": 0, "tn": 0, "late": 0}
    if unit == "day":
        stopped = {int(r.day) for r in L[(L["event"] == "day") & (L["detail"] == "stopped")].itertuples()}
        fault = {int(d) for d in labels[labels["kind"] == "fault"]["day"]}
        for d in range(1, days + 1):
            f, s = d in fault, d in stopped
            c["tp" if f and s else "fn" if f else "fp" if s else "tn"] += 1
        n = days
    else:
        sw = sorted((int(r.day), r.chamber, float(r.value)) for r in labels[labels["kind"] == "swap"].itertuples() if int(r.day) <= days)
        flags = sorted((int(r.day), r.chamber) for r in L[L["event"] == "flag"].itertuples() if int(r.day) <= days)
        base = sorted((int(r.day), r.chamber) for r in L[(L["event"] == "request") & (L["detail"] == "baseline")].itertuples() if int(r.day) <= days)
        other = {(int(r.day), r.chamber or "전체") for r in L[(L["event"] == "request") & (L["detail"] != "baseline")].itertuples() if int(r.day) <= days}
        ufl, ubs, ex = set(), set(), 0
        for d, ch, eff in sw:
            pos = abs(eff) >= DELTA_H
            if d + grace > days:                      # 판정 기한 전: 칸에서 빼고 이 챔버의 이후 신호도 헛으로 세지 않음
                if unit == "request" or pos:
                    ex += 1
                _pending(flags, ufl, ch, d)
                _pending(base, ubs, ch, d)
                continue
            if unit == "change":
                if not pos:
                    continue
                j = _first(flags, ufl, ch, d, d + grace)
                if j >= 0:
                    ufl.add(j)
                    c["tp"] += 1
                else:
                    c["fn"] += 1
                    k = _first(flags, ufl, ch, d + grace + 1, days)
                    if k >= 0:
                        ufl.add(k)
                        c["late"] += 1
            else:
                j = _first(base, ubs, ch, d, d + grace)
                if j >= 0:
                    ubs.add(j)
                    c["tp"] += 1
                else:
                    c["fn"] += 1
                    k = _first(base, ubs, ch, d + grace + 1, days)
                    if k >= 0:
                        ubs.add(k)
                        c["late"] += 1
        if unit == "change":
            c["fp"] = len({(d, ch) for i, (d, ch) in enumerate(flags) if i not in ufl})
            n = days * len(CHAMBERS) - ex
        else:
            c["fp"] = len({(d, ch) for i, (d, ch) in enumerate(base) if i not in ubs} | other)
            n = days * (len(CHAMBERS) + 1) - ex
        c["tn"] = n - c["tp"] - c["fn"] - c["fp"]
    pos = c["tp"] + c["fn"]
    c.update(n=n, pos=pos, agree=(c["tp"] + c["tn"]) / n, all_no=(n - pos) / n)
    return c


def wilson_ci(k, n, conf=0.95):
    """비율 k/n 의 윌슨 구간 (낮은 끝, 높은 끝)."""
    z = NormalDist().inv_cdf(1 - (1 - conf) / 2)
    p = k / n
    den = 1 + z * z / n
    ctr = (p + z * z / (2 * n)) / den
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / den
    return max(0.0, ctr - half), min(1.0, ctr + half)


def eval_policies(log, labels, grace=GRACE, days=DAYS):
    rows = []
    for pid, pname in POLICIES:
        for uid, uname in UNITS:
            c = agreement_table(log, labels, uid, pid, grace, days)
            lo, hi = wilson_ci(c["tp"] + c["tn"], c["n"])
            rows.append({"policy": pname, "unit": uname, **c, "lo": lo, "hi": hi})
    return pd.DataFrame(rows)


# ---- 2. 계획 모델과 sim-real gap ------------------------------------------------------
def plan_model(leave, repair, params, system=None):
    """마스크가 in_use 를 떠난 시각 leave 에서 '다시 stock 에 들어오는 시각'을 미리 센다.
    system=None: 평균값만(세정 대기·짝 대기·고장 무시). system=(세정 중 끝날 시각 목록, 대기 줄, 오는 중 목록): 세정기 대기열을 먼저 따져 본다."""
    cap, tr, cl, ts, rm = (params[k] for k in ("CAP", "TR", "CLEAN", "TOSTK", "REPAIR_MED"))
    if system is None:
        return leave + tr + (rm + cl if repair else cl + ts)
    running, waiting, transit = system
    own = leave + tr + (rm if repair else 0)
    items = sorted([(leave, t) for t in waiting] + list(transit) + [(own, 10 ** 12)])
    free = list(running) + [leave] * max(0, cap - len(running))
    start = None
    for arrive, order in items:
        free.sort()
        s = max(arrive, free[0])
        free[0] = s + cl
        if order == 10 ** 12:
            start = s
    return start + cl + (0 if repair else ts)


def sim_real_gap(trace, params):
    """실제 전이 기록(0206 trace)의 마스크 경로마다 계획 모델 두 판의 예측과 실제 stock 입고 시각의 차(예측 − 실제, 분)."""
    tr, cl, rm = params["TR"], params["CLEAN"], params["REPAIR_MED"]
    m = trace[trace["entity"] == "mask"]
    state, open_, rows = {}, {}, []
    for t, i, a, b in zip(m["t"], m["id"], m["from"], m["to"]):
        t = int(t)
        if a == "in_use" and b in ("to_clean", "repair"):
            rep = b == "repair"
            running, waiting, transit = [], [], []
            for k, (s, t_in) in state.items():
                if k == i:
                    continue
                if s == "cleaning":
                    running.append(max(t, t_in + cl))
                elif s == "clean_wait":
                    waiting.append(t_in)
                elif s == "to_clean":
                    transit.append((t_in + tr, t_in))
                elif s == "repair":
                    transit.append((t_in + tr + rm, t_in))
            open_[i] = {"id": i, "kind": "리페어" if rep else "정상", "t0": t, "plan1": plan_model(t, rep, params), "plan2": plan_model(t, rep, params, (running, waiting, transit)), "wait": 0, "held": 0}
            rows.append(open_[i])
        o = open_.get(i)
        if o:
            if a == "clean_wait" and b == "cleaning":
                o["wait"] = t - state[i][1]
            if a == "held" and b == "to_stock":
                o["held"] = t - state[i][1]
            if b == "stock":
                o["actual"] = t
                del open_[i]
        state[i] = (b, t)
    df = pd.DataFrame([r for r in rows if "actual" in r])
    df["gap1"] = df["plan1"] - df["actual"]
    df["gap2"] = df["plan2"] - df["actual"]
    return df


def gap_summary(g):
    out = {}
    for name, sub in (("전체", g), ("정상", g[g["kind"] == "정상"]), ("리페어", g[g["kind"] == "리페어"])):
        for v in ("gap1", "gap2"):
            x = sub[v]
            out[(name, v)] = (len(x), x.mean(), x.std(ddof=1), x.abs().quantile(0.5), x.abs().quantile(0.9))
    return out
